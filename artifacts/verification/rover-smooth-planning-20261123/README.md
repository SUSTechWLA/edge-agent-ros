# 轮式车局部规划的平滑性与响应时间

工作站上从 DSH 目录解析 `planning.local_path` 1.1.0，再通过 HTTP 向常驻进程提交车体快照。Agent 任务工具和单帧机器接口共享同一规划器。规划结果携带算法、采样时刻、车体坐标系、整段曲率上界和观测覆盖。两个入口都只返回建议。[插件契约](../../../perception/rover_preview/README.md)

## 相同数据上的绕行对照

旧版和新版分别读取同一份 Gazebo 中央箱体初始扫描，使用相同的车身外廓、0.55 m 净距要求和 3.45 m 前向目标。这个目标来自仿真记录，现场配置的默认规划距离为 2.60 m。规划器只看传感器观测。独立评分程序用世界中的障碍轮廓和完整矩形车身，扣除采样间隙可能产生的误差，得到整段车身扫掠净距的保守下界。

| 中央箱体 | 历史折线 | 五次曲线 |
|---|---:|---:|
| 规划路径长度 | 5.027 m | 4.719 m |
| 相邻显示线段的最大航向变化 | 63.78° | 3.83° |
| 独立真值净距下界 | 0.7283 m | 0.5597 m |
| 沿途观测覆盖 | 84.3% | 82.6% |

新版由进入绕行、通过、回到目标方向三段组成，在连接处保持位置、切向和曲率连续。123 个返回点用于前端绘制。上表中的角度受采样密度影响，连续性来自曲线本身。整段曲率上界为 3.136 /m，低于本轮预览配置的 5.0 /m。相对门限的几何余量为 9.7 mm，实际车体跟踪误差、标定误差和制动还需在闭环中测量。该路线以 `partial` 返回。Jetson 历史近障快照中，车身到可见表面只有 0.041 m，两版均返回保持原位及空路径。[旧版](baseline.json) · [新版](replay.json) · [仿真预览截图](smooth-path.png)

从本机打开 [13.6 秒前端录像](smooth-plan.mp4) 或 [可交互回放](smooth-plan.html)。录像先展示中央箱体的候选路线、正俯视和图层开关，再切换到 Jetson 历史感知帧。浏览器离线验证了 123 个路径点、现场空路径、可逆的图层操作和视角切换。回放和视频包含现场相机画面，随本机交付。

## 逐帧响应

每种输入预热后顺序调用 60 次。算法列来自 Windows AMD64 上的单进程调用；HTTP 列来自限额一个 CPU 的 Linux x86-64 容器，含本机客户端编码、每次新建连接、服务计算、答复解码。两列使用同一份观测几何，HTTP 测试更新时间戳以通过实时入口的接收检查。

| P95 | 算法 | HTTP 往返 |
|---|---:|---:|
| 空场 | 0.61 ms | 3.40 ms |
| 中央箱体 | 8.70 ms | 13.97 ms |
| 实车历史近障帧 | 0.51 ms | 2.99 ms |
| 3,105 个回波的合成压力输入 | 27.22 ms | 43.91 ms |

默认 50 ms 软截止在计算返回时检查，忙时直接拒绝，超时返回空路径。本组压力请求最长 45.91 ms。现场传感器产出、传输、感知融合和 Jetson 并发负载另计。机器接口按调用方推送评估，尚待连续传感器流及原生 Jetson 负载验收。[响应统计与源码散列](http-linux.json) · [几何复算脚本](../../../tests/system/rover_preview_replay.py) · [HTTP 测时脚本](../../../tests/system/rover_preview_http_timing.py)

工作站通过 25 项轮式车测试和 10 项现场数据回归。Linux ARM64 仿真容器通过 8 项规划和 5 项服务契约测试。契约测试使用固定时钟验证输入年龄及计算预算；上表使用实时时钟。实际 HTTP 客户端脱离一个长任务后，后台任务完成即释放容量，同一操作可重新读取原收据。

## 任务组合与物理边界

| 用途 | 可复用的接口 | 本轮边界 |
|---|---|---|
| 静态避障 | 当前车体观测、机型和可选短程目标产生候选曲线。上层可传入上一帧的绕行侧偏好 | 净距、曲率、超时、繁忙、陈旧及坐标系受检。覆盖不足保留 `partial` |
| 区域探索或全局导航 | 上层选择前沿或全局路径的下一个局部子目标，转换到车体坐标后复用同一服务 | 已测显式前向子目标。探索选点、多地图切换及倒车分别需要上层策略或适用的规划提供者 |
| 动态避障 | 跟踪器可独立提供带时间的障碍预测，时空规划器结合速度、加速度和制动约束计算轨迹 | 当前静态服务明确拒绝动态请求。已有 Gateway 的仿真横穿让行有独立验收；这次曲线只经离线回放 |
| 其他机型 | 复用任务意图、发现、绑定、时效和只读结果语义 | 飞行器的三维空间和机械臂的关节空间需各自的运动学与碰撞检查 |

DSH 的只读软件服务由调用方固定版本；任务重试读取其原操作和收据。Gateway 现有的独占运动授权、逐拍跟踪与制动独立运行。本轮没有变更控制层或部署到 Jetson。[系统协议](../../../docs/specs/SDD-056-rover-local-plan.md)
