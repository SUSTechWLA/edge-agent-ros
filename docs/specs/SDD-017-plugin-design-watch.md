# SDD-017 · 从现场能力缺口自动交付插件设计

## 背景与价值

基线 `b96a86e` 已能为预授权的只读声明补齐工具。若目标超出现有算子，作者保存带证据的拒绝，部署者需要手工找到导出的拒绝事件与相应私有决定，才能调用 SDD-013。长任务的开发交接因此依赖有人值守。新增一个可单独启停的事件消费者，把这一步变成有持久工作记录的后台操作。

## 设计与契约

1. 从受信任 Console 分页订阅 `source=journal:plugin.author`、`module=plugin.author`、`kind=plugin.author.declined`、`code=author.proposal_rejected`。只读打开作者 `decisions/<receipt_id>.json`。按 SDD-013 校验摘要、父事件、原任务、拒绝原因和原请求，按显式配置读取允许提供给模型的契约目录。
2. 原始拒绝身份标识一项工作。工作表记录接收、尝试、延迟重试、完成或需要人工介入，公共事实带来源、任务、trace、父事件与操作身份。对同一身份与不同内容的重复记录给出冲突证据。归档换代导致同一拒绝再次出现时沿用原工作。
3. 在磁盘登记尝试后才允许调用模型，恢复时先检查原草案和收据。成功交付沿用原生 `plugin.design.drafted` 与私有草案格式，供 SDD-014 复用。已写入但尚未确认的审计与工作状态可对账。事件日志和进程标准输出只留标识、原因码和证据摘要。
4. 默认最多三次尝试。缺少收据、模型暂时离线或模型输出不满足契约时有界重试；身份、摘要或已有草案冲突进入人工介入。进程可能在远端模型已经受理、本地尚无结果时退出，此次计入预算。未保存的模型答复可能需要再次推理。归档不可读时已落地工作可继续；逐源覆盖情况通过 SDD-016 的订阅事件查询。
5. 本插件仅写自己的工作目录、草案与事件源。每份草案的 `review_state` 为 `unverified`，开发和发布分别沿用 SDD-014 的隔离、独立验收和批准流程。原生受阻任务及物理动作仍由原所有者管理。

## 验收与证据

| AC | 输入与可观察的结果 |
|---|---|
| AC-1 | 一条自然语言任务产生可信拒绝，消费者自动查收收据与可用契约。原任务仍受阻，私有草案和公开父链可核对，摘要对应实际工件。 |
| AC-2 | 归档重放、换代重收和重启不重复交付。最后一次尝试在工件写入后退出，重启可确认已写草案。已受理但未经本地确认的模型调用计入预算。 |
| AC-3 | 超时或无效模型输出在预算内重试，耗尽后只报一次人工介入及操作。有缺失、改动、路径越界或无目标的收据时单条隔离，其他合法任务仍可生成设计。 |
| AC-4 | 总线断连、裁剪或换代可从订阅事实识别。模型只接触明确许可的目标和契约，公开源不含原始任务正文、草案或模型输出。 |
| AC-5 | 可单独安装或停用，恢复时沿用原状态、游标与事件卷。Docker 故障实验同时核对原生任务、工具调用次数、模型生成次数和原来源身份。 |
| AC-6 | 上游模型或归档成功建立连接后持续缓慢发送字节。一项读取必须在整体墙钟预算内返回，留下模型失败或订阅受阻的原因，排队中的其他工作仍能推进。DNS/TCP 建连也占用同一预算。 |
| AC-7 | 写草案前由作者持久登记该尝试的输入收据、设计 ID 与预期工件 SHA-256。若进程在写文件后、发布成功事件前退出，恢复时只认可与事先登记摘要一致的全部原始字节。改写目标、模型建议或权限字段均触发单条人工介入。已完成的历史设计可用原成功事件对账；只有旧文件、没有成功事实或写前承诺时须人工复核。 |

## 迁移与回退

CLI 接收 `--url`、`--decisions`、`--state`、`--journal`，另可指定 `--ollama-url` 与 `--model`、`--contracts-dir`、`--attempts` 和 `--once`。两项模型参数为空时生成待研发者补全的离线设计简报。私有输出为 `<state>/drafts/<design_id>.json`。一次模式处理当前已到期的工作和归档分页。通过持续运行或稍后重新调用接续退避中的工作。停止服务并保留卷即可回退；如需再次处置人工项，复核原事件与私有决定后使用已有 SDD-013 CLI，保留原事故记录。

SQLite 及私有输入输出依赖本机持久卷。丢失工作卷后需与原事件源和私有草案核对，在核对前暂停订阅。模型生成与本机事务没有跨网络的原子提交。主机突然断电、存储丢失和恢复用时在指定板卡上另行验收。
