# SDD-032 首次上板的只读入口与传感器验收

## 背景与价值

在 864bcdb 上，`hardware up perception console` 会检查一次工作台 HTTP 响应，然后报告就绪。此时三个驱动可以全部离线。硬件工作台使用 host 网络，即便该次部署没有选择 Agent，也会把任务提交和重试转发到宿主 8090。首次上板需要分别确认工作台是否启动，以及机器人自己的传感器是否在正确的坐标系和时间域内连续出样。

## 设计与契约

扩展现有 `scripts/deploy.sh hardware` 入口与工作台代理。新增 `observe` 仅启动感知和工作台，拒绝通过该工作台派发任务，也拒绝悄然切换正在运行本项目控制服务的部署。新增 `preflight [odom imu scan]` 在已启动的工作台容器内读取其回环 HTTP 接口，按当前部署参数核对设备标识、ROS 话题、实测父子 frame、采样新鲜度、传感器时钟和时间戳推进。缺省检查三项，实际所需传感器可明确指定。输出含版本、架构、身份、会话、问题和各源时间的 JSON，体积与检查通道数相关。内核、驱动、运动权限与现有任务账本继续由原模块持有。

## 验收与证据

| 编号 | 预期 |
|---|---|
| AC-1 | 只读工作台在上游 Agent 可达时也拒绝任务和重试，GET /api/state 与历史可读。完整模式保留原有代理行为。 |
| AC-2 | 无驱动时工作台可启动，预检以非零状态和缺失话题结束。同一端口上的仿真工作台不能冒充真机。 |
| AC-3 | 接入合成 ROS 驱动后用实际硬件部署进程验证采样。停止、错帧、时钟偏离及重复旧戳时不能通过。新会话不能拼接旧采样。 |
| AC-4 | 完整模式和单独预检兼容。启动参数错误在启动服务前报错。有可复用的本地和离线镜像、板端命令及证据归档说明。 |

## 迁移与回退

旧部署仍可使用 `hardware start` 与 `up`。只读模式需要含本规格的镜像。停止只读服务保留历史卷。完整模式需明确启动，物理驱动、制动、外参、网络延迟及真机负载在各板卡单独验收。
