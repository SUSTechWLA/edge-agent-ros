# SDD-011 · 模块事件缺口与归档恢复证据

## 背景与价值

基线 `50b9344`。Console 按插件源序号归档关键事实。若源库只剩第 1、4 行，当前消费者看到两条正常事件，无法知道第 2–3 个位置未读到。当前源可用性存在 Console 的内存字典内，归档器在一次源故障中重启后，会丢失“恢复”与“先前中断”的联系。复盘者需要了解哪部分证据缺失，才能判断一次插件升级或重试是否真的成功。

## 设计与契约

复用 ModuleJournal、Console 归档与 `GET /api/events`。变更位于归档消费者 `journal.ingress`，所有者为 Console。源端继续拥有其事实，Agent、运动内核及插件发布者按原协议决定执行和终态。

- 在同一源身份中，若下一条实际行的序号大于已确认游标加一，Console 先提交一条 `module.journal_gap`。记录源模块、源身份、未读区间和下次实际看到的序号。使用缺口末位作为该条归档诊断的源游标，崩溃后从下一位置恢复。新源首行大于 1 也适用。仅能确认观察到的序号缺口，无法推断缺失了哪项业务、源在最后一条后是否还产生过事件。
- 对第一次观察为可读的来源记录基线。按模块追踪可读、缺失、读库失败和恢复。归档保留最近状态和事件 ID，Console 重启后继续同一因果链。同一状态不重复发出。插件目录整体读取失败时记录目录状态，避免对目录下各插件的存在作出推断。
- 以上诊断写入归档后可按 `source=edge_console`、`module=journal.ingress`、trace、code 读取。变化发生时间使用 Console 的观察时间。错误证据只含受控标识、稳定分类、范围等元数据。

## 验收与证据

| AC | 输入 | 可观察判据 |
|---|---|---|
| AC-1 | 缺失前缀与中间序号，同批仍有健康源 | 每个区间恰有一次诊断，随后有效行和其他源正常收录，源身份独立。 |
| AC-2 | 缺口诊断写入后且实际行写入前中断 | 恢复后同一缺口不重报，实际行被收录。 |
| AC-3 | 源消失，归档器重启，再次观测缺失与恢复 | 保留一次故障、一次恢复及父事件定位；连续巡检不产生噪声。 |
| AC-4 | 源字节/状态异常，正常插件仍工作，公开接口按来源和 code 查询 | 归档诊断注明观察者与稳定分类，异常载荷和私有路径不进入公共错误数据。 |

## 迁移与回退

新诊断复用现有归档表。旧归档保留原事件，从升级后首次观测开始建立可用性链。旧读者按既有信封读取新增 kind。部署时替换 Console。回退同样替换 Console 并保留原卷，旧读者可以读历史诊断。已越过的源序号按原游标保留，不能从不可见历史重建缺失内容。
