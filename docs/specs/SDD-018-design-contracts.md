# SDD-018 · 给设计 Agent 提供可热更新的扩展接口

## 背景与价值

基线 `b96a86e` 的设计作者将 Tool、Service 和 Event consumer 三项接口直接写入提示。项目同时支持额外 ROS 传感器观测以及独立结果验收器。新人可以读到相应协议，模型收到的设计输入却缺少这些具体接口。新增一种扩展方法需要让部署者能直接给作者提供受版本管理的契约。

## 设计与契约

部署者在只读的 `contracts/design/` 放入小型 JSON 文件。每个文件列出接口 ID、版本、状态所有者、输入、输出、独立验收、卸载/回退方式和仓库内的规范位置。每次设计请求读取一次有界快照，同一快照用于模型可选接口、请求内容、草案和完成事件。公开事件保存摘要与接口数量，草案保存当时所见的接口。引用路径仅供开发者定位，作者不会打开引用中的文件。新增接口在下一次设计时可见。目录中移除接口后，旧草案仍可按原摘要复查。

启用目录的 CLI 和订阅作者复用同一行为。目录未配置时兼容原有三项接口；配置了不可读、冲突或不合规的文件时留下失败事实。接入新接口描述只影响设计阶段，工具的安装权限、动作的运行授权和独立结果验收仍由实际所有者决定。

对已配置目录，作者在首次实际使用及随后内容改变时保存 `plugin.design.contracts_observed`，按同一目录身份关联前后摘要与当次请求。私有 `drafts/.contexts/<摘要>.json` 在调用模型前固定该请求所见材料，即便模型出错也能复盘。两次请求之间未被任何设计读取的中间文件状态超出该观察范围。

## 验收与证据

- AC-1 更改、增加、撤下接口后，新设计使用当次快照；同一输入和相同内容可重用原工件。旧草案的材料和摘要可读。
- AC-2 模型可选接口由该快照生成。拒绝未登记的接口；失效清单、重名、超预算、目录逃逸不得触发无依据的设计或模型调用。
- AC-3 在隔离 Docker 中从真实的任务受阻事实和作者决定启动设计，在公开事件查到契约摘要，可与私有草案独立对账。设备观测与纯软件验收接口各有样本。手工 CLI 和运行中的消费者仍能工作。

## 迁移与回退

独立 CLI 可指定 `--contracts-dir`；Compose 为设计插件单独挂载目录。撤回文件时先在工作目录保存已部署版本，用原子改名替换单个文件。停用可选目录可使用内置接口。提供者、进行中的设备任务和旧草案按各自生命周期维护。
