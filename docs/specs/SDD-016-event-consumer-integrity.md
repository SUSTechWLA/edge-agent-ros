# SDD-016 · 插件订阅的事实校验与恢复证据

## 背景与价值

以 `b96a86e` 为基线，作者和管理器从 Console 的 HTTP 事件页读取能力缺口和发布提案。共享的 Sink 对已有 `(archive_id, seq)` 使用 `INSERT OR IGNORE`。如果另一个筛选条件读到相同位置却返回不同事实，会保留旧行并确认新的检查点。页面乱序、数据超出游标或来自错误来源，也可能进入工作队列。处理错误的输入后再检查业务策略，已经失去了可靠的取证起点。

## 设计与契约

沿用公开 HTTP 游标和 SQLite。先检查归档身份、覆盖与裁剪上界、事件显式位置与顺序、分页标记以及精确筛选字段，再将整页原件和游标同事务提交。筛选后的序号可以跳跃。归档的全局裁剪水位意味着一些位置可能已经缺失，无法断言订阅的哪项工作一定丢失。已有位置重放只接受相同事实，允许 Console 对同一 `parent_event_id` 补录 `cause_seq`。多个归档世代使用各自的原件与游标。

消费者自己记录阻塞、恢复和已观察的裁剪风险，记录检索位置和稳定原因码。错误载荷、URL、私有提示和任意异常文本不进入诊断。模块通过自己的 ModuleJournal 发布这些事实，跨库传递使用持久待投递记录和稳定事件 ID。恢复成功需要实际提交有效页面。订阅协议不能证明数据源从未隐瞒事实，也不能替一个模块认领任务或授权发布。

## 验收与证据

| AC | 故障和预期 | 验证 |
|---|---|---|
| AC-1 | malformed JSON、身份或行形状非法、游标超范围、截断、乱序、重复序号或实际行违背精确过滤条件。整页拒绝，游标与原件保持原状态。 | 临时 HTTP/SQLite 与页级故障夹具 |
| AC-2 | 不同订阅读到同一位置。相同事实允许重放，晚到父事件可补齐位置，内容冲突时回滚整个批次。 | 同库多选择器重放 |
| AC-3 | 订阅跨重启持续遇到同一故障。只保留首次阻塞，恢复后有带父事件的恢复；裁剪水位覆盖读取窗口时保留范围。公开事件无异常原文。 | SQLite、ModuleJournal 与重启测试 |
| AC-4 | 崩溃位于诊断私库提交与模块事件发布之间，或发布后确认之前。重开继续投递，源中的事件 ID 相同。旧 SQLite 使用原表和旧游标，旧的作者/管理器照常运行。 | 故障注入与既有回归 |

## 迁移与回退

用新镜像重建相应的订阅进程并继续使用原卷。新增的诊断表与原件表、检查点相互独立，回退到旧消费者可继续从已提交游标工作。回退后失去本规格的校验与诊断。历史上已经确认的错误页需用可信源和独立备份人工核查。源库不可写时无法在该库留下新证据，应由外部 Watchdog、容器日志及独立存储监督。

2026-11-18，AC-1 至 AC-4。实现位于 [Sink](../../client/event_sink.py)，作者与管理器把运行诊断绑定到自己的 ModuleJournal。单页上限 32 行、8 MiB；检查 int64 序号、严格递增、全局水位和精确筛选条件。同位置全文冲突阻塞，带 `journal:` 来源的已发布事件 ID 也不能出现在同一归档的第二个位置。其他来源可能存在同 ID 的投影，消费者依来源分辨。只有同一父事件的未解析因果位置可以补齐。Console 重启时以存活最大序号与已裁剪高水位的较大者恢复游标。

隔离 Docker 使用本机 `edge-agent-ros:plugin-evolution-49ee6f2` 镜像、只读挂载本次 client 和 console/server。命令 `python3 -B -m unittest discover -v -s /opt/edge/console/server -p test_event_sink.py` 的 8 项全部通过。一次真实 HTTP 页损坏后，在不同 Sink 实例间重试，只生成一条阻塞事实。恢复后用公开归档查到两条事实的同一 trace 与父子 seq，本地仅收到一条可信业务事件。额外用例覆盖旧表、跨选择器同位置冲突、二次绑定同一源事件 ID、整批回滚、裁剪、空归档重启和跨账本确认时崩溃。Windows 上既有作者 5 项、管理器 14 项通过。选定依赖有了失败证据，进程整体断电、磁盘不可写或长时间 DNS 阻塞仍需独立监督。[测试源码](../../console/server/test_event_sink.py)
