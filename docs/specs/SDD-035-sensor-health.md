# SDD-035 端侧传感器质量巡检与恢复确认

## 背景

传感器话题仍在更新时，整幅图像可能已过曝或没有纹理，深度数据也可能大面积缺失。现场需要在一次任务失败后找到具体传感器、原始测量时间、异常持续状态及后续恢复依据。室外开阔地可以产生零近场回波。图像纹理只能反映特征提取条件，求解器实际接受了多少匹配应从定位前端读取。

## 接口

可选 Compose 插件 `sensor-health` 订阅用户选择的 ROS 2 Image、LaserScan、PointCloud2 和 Imu，支持仿真与 Linux 实机。另可订阅前端发布的带时间、坐标系、匹配总数和内点数的只读统计。原始字节保留在 ROS，审计只保存有界抽样产生的标量、话题、frame、采样时间、时延和错误原因。通过模块 `sensor.health` 的持久 EventBus 账本进入工作台事件页，HTTP 状态快照供值班和自动检查使用。

## 验收

1. 分别注入正常图、黑图、过曝、弱纹理、深度空洞、无效或稀疏点云、开阔地无限距离激光及无效 IMU。逐类核对指标与事件原因。雷达开阔和视觉纹理退化不直接推导 SLAM 已丢失。
2. 附加匹配统计后，明确标注该指标由前端报告；没有统计输入时标为未配置。注入异常时戳、错误编码、断流与重复帧，保留诊断。时间差以同一个声明的 ROS 时钟为基准，断流计时使用单调时钟。
3. 异常后在预算内等待新的独立帧，只有连续新鲜正常样本才能确认恢复；持续异常给出人工检查提示。重复同一状态的高频消息不重复灌入事件流。
4. 插件单独启停，进程没有运动发布器、ROS 参数写入、硬件 IO 和重启驱动接口。停机期间由 EventBus 心跳机制和消费者判断数据可用性。模拟器不依赖此插件启动。
5. 既有 Agent Tool 协议可读取同一份观测。只读 `POST /diagnose` 接受版本 1、operation_id、scope 为“本机”“当前”或“导航”；输出同一 operation_id、非空中文摘要、各配置源当次测量、frame 和事件引用。未配置和缺测应有说明。使用者可从自然语言请求进入会话，再用源事件 ID 追查原始诊断。

## 范围

本轮交付测量质量判断和有界复核。视觉或激光里程计、完整 SLAM 解算、机器人执行停车与实机调参分别由已有执行方或后续具体验证负责。
