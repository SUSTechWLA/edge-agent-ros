# SDD-035 端侧传感器质量巡检与恢复确认

## 背景与价值

传感器话题仍在更新时，整幅图像可能已过曝或没有纹理，深度数据也可能大面积缺失。现场需要在一次任务失败后找到具体传感器、原始测量时间、异常持续状态及后续恢复依据。室外开阔地可以产生零近场回波。图像纹理只能反映特征提取条件，求解器实际接受了多少匹配应从定位前端读取。

## 设计与契约

可选 Compose 插件 `sensor-health` 订阅用户选择的 ROS 2 Image、LaserScan、PointCloud2 和 Imu，支持仿真与 Linux 实机。另可订阅前端发布的带时间、坐标系、匹配总数和内点数的只读统计。原始字节保留在 ROS，审计只保存有界抽样产生的标量、话题、frame、采样时间、时延和错误原因。通过模块 `sensor.health` 的持久 EventBus 账本进入工作台事件页，HTTP 状态快照供值班和自动检查使用。

提供者独占自己的事件库，每个源独立维护最近观测、采样复核预算和恢复计数。HTTP 提供即时状态，已有 Console 摄取模块事件，`diagnose_sensors` 通过既有只读 Tool 接口把快照带入当次任务。运行时可以撤下 Tool 注册和订阅服务，仿真与运动控制独立继续。变更源配置需要重新创建该订阅服务。订阅状态在进程重启后重新测量，历史事件继续使用同一卷。[运维、阈值与协议](../../perception/sensor_health/README.md)

## 验收与证据

| 编号 | 可观察的通过条件 | 证据与范围 |
|---|---|---|
| AC-1 | 黑图、过曝、弱纹理、深度空洞、无效点云、异常扫描与 IMU 给出对应原因。少量有效 3D 点与合法的开阔地无近场回波有独立信息状态。 | 隔离 ROS 发布进程注入 Image、LaserScan、PointCloud2、Imu；对照数据由测试生成，检查原始指标、输入名称和事件。 |
| AC-2 | 视觉或激光匹配的证据能标出前端来源。错误时戳、重复帧、断流与错误 frame 可区分。 | 独立小型视觉匹配程序在两对测试图像上实测 36/36、1/36，作为报告输入；未配置激光前端时返回未配置。实际产品定位器和地图漂移精度需另测。 |
| AC-3 | 故障经有界重采样后上报持续异常，只有连续三份新鲜有效观测才确认恢复。每步转换保存原因、最近观测、父事件引用和预算。 | 在短计时预算下独立触发 14 类异常，14 类均恢复。相同状态的高频采样不逐帧写入。 |
| AC-4 | 观察者可独立启停与挂载。启动、观测、告警、恢复可由已有 EventBus 发现。 | ROS 进程使用订阅者；隔离运行只提供临时目录和回环网络。日常校园单独启用巡检。实机时钟同步、各设备阈值、断电后调度与恢复需板上验收。 |
| AC-5 | 只读 `POST /diagnose` 接受版本 1、操作 ID 和一个范围，回传同一 ID、中文摘要、每源最近测量和事件引用。 | “本机”“导航”“当前”三组可读，其他机器范围被拒。单次查询在当前机器人内完成；事件按来源和时间定位。 |
| AC-6 | 同一插件可按话题和 frame 配置读不同机器人拥有的传感器。 | 单独的三机实验采集 Gazebo 原始帧并仅在隔离域注入故障。Crazyflie 黑图后恢复，Go1 稀疏保留信息态、损坏点云触发告警后恢复，G1 深度空洞后恢复。过曝在通用 RGB 故障夹具中独立验证。各机测量以[逐帧回放证据](../evidence/edge-field-sensor-replay.json)与[机型报告](../testing/edge-field-faults.md)为准。真实机体的光照、运动恢复、地图定位与自动曝光控制仍待实测。 |

## 迁移与回退

校园启用命令是 `python scene/campus_large/run.py sensor-health --image <本地镜像>`。替换或卸载时先撤下同一 Tool 描述，再停止订阅服务，保留模块卷和 Console 归档。回退至旧镜像时核对旧版是否包含 `perception/sensor_health`。视觉里程计、激光 SLAM、停车动作和硬件调参分别由定位器、执行器及设备管理提供者负责。
