# SDD-055 可组合感知与多构型机器人规划

状态：部分实现。设计基线为 `b58c88f`。本轮交付覆盖同一 RGB-D 归档上的障碍复核，以及相同结果契约的多实现选择和停用切换。其余机型规划、通用多输入图与持续感知仍属设计。

## 背景与价值

用户提出“看看前方哪里需要先复核”。上一次 Jetson 试验曾正确返回深度统计，却没有回答复核顺序。要判断一次任务是否完成，系统必须知道用户需要哪种结果、结果适用于什么主体、用什么事实可以验证它。同样，“规划一条路线”对轮式底盘、无人机和安装在底盘上的机械臂有不同的物理含义。

现有代码有四个可复用的基础和三个明显的扩展缺口。

| 当前入口 | 在本设计中的作用 |
|---|---|
| DSH v2 的 Tool、Service、pack/profile、冻结绑定与排空 | 继续负责真实实现的装卸、调用和版本追溯。每个导出名只有一个所有者。见[描述符](../plugin-descriptor-v2.md)和[软件宿主](../../agent/soft_runtime.py)。 |
| 空间观测、已发布数据读者、区域统计 | 原始事实已有主体、来源、时刻、时钟、坐标系、标定及制品引用。采集、融合、复核可以有不同消费者。见[观测契约](../../edge_contracts/spatial_facts.py)和[分区复核插件](../../perception/spatial_facts/authored_screen.py)。 |
| 只读任务计划、已验收的现场创作 | 当前步骤主要表达工具和字面参数，缺少通用的步骤间类型化引用。创作范围由站点声明，但受支持的作者族在程序中枚举，安装识别还依赖命名空间。见[任务规划](../../agent/planning.py)、[范围匹配](../../agent/read_plugin_families.py)和[创作服务](../../client/field_plugin_watch.py)。 |
| 导航域与物理 runtime | 已有按主体和地图生成的路线、地图及定位版本绑定。现有路线以二维或三维点表达，算法选择集中在栅格/图和 A*/Dijkstra。机械臂需要独立的关节空间与场景契约。见[路线契约](../../edge_contracts/navigation.py)、[路线算法](../../navigation/planner.py)及[导航规格](SDD-051-unified-navigation.md)。 |

## 设计与契约

### 1. 能力定义、实现与调用

沿用 DSH 的术语。**Definition 描述可以取得的结果，Provider 给出一种具体实现，Tool 是按需提供给 Agent 的操作。** 站点 pack/profile 决定这台机器可用哪些实现和权限。高频的基础事实和计算优先作为 Service，任务层常用操作才导出 Tool。

建议在 pack 中引入独立版本的能力索引，用锁文件固定其摘要。索引是 DSH 目录的只读投影。每个条目引用现有的唯一导出名和接口版本，记录输入输出 schema 及语义版本、单位和参考系、适用主体或子系统、必需事实、质量范围、效果、计算预算与验收器。作者来源和实现语言另记在 provenance。安装健康、资源可用、授权与实际绑定均以运行时为准。老 v2 描述符按原格式加载。

例如，两个实现都能提供“已观测空间的局部占据栅格”，但分别导出唯一服务名。只有输出遵守相同的坐标、分辨率、占据含义、未知区域规则和有效期，才可列为同一契约的候选。只给相机分区深度的实现可满足“近距复核”，无法满足“底盘占据栅格”。

任务规划器提出目标和契约。部署侧解析器先按主体、输入和时效、权限、输出保证、算法适用范围和预算过滤，再按站点优先级和实时健康排序。选定后，计划记录具体导出和依赖闭包的冻结 binding。按需生成带已选依赖的受信组合绑定，或在现有调度器派发前解析到具体 Tool。所有可选算法无需成为同一个 Provider 的必需依赖。冻结后任一依赖丢失，未派发的分支可建立有证据的新计划版本，在途操作按原号核对。多个算法同时参与融合时各有节点、权重或决策规则和独立来源。

### 2. 感知层的四种入口

| 用户已有的东西 | 接入方式 | 哪些工作可以复用 |
|---|---|---|
| 系统内置实现 | 内置 pack 注册独立 Provider，例如图像测量、时间同步或坐标变换。 | 导航、巡检、机械臂和前端可消费同一份事实。 |
| 用户写好的 workflow | 已有 Python/C++ 流水线或其他引擎可在隔离进程中包装成单个 Provider，只要求适配边界输入输出、健康、取消和证据。愿意暴露内部步骤的用户也可提交声明式组合。 | 可复用整条已调好的流水线，或选择显式导出的中间产物。黑盒只展示外层回执。 |
| Agent 按任务临时组合 | 在本次任务中连接已授权能力的类型化端口并冻结绑定。一次性图随任务保存。具有复用价值的图，经独立验收、版本化和发布才进入站点目录。缺少原子能力时，可委托站点已注册并批准的作者插件开发候选。 | 一次任务即可使用已有工具。发布后的组合可被下一任务、其他插件或工作流调用。 |
| ROS 已有的感知栈 | 通过部署时批准的独立桥接进程消费现有观测或结果，记录 topic、消息类型、QoS、时间、TF、节点身份和来源，再转为内部事实。已有 ROS 算法可整体作为 Provider。 | 同一结果既可由 ROS 提供，也可由录包或本地算法提供。是否使用 ROS 与代码作者是两个维度。 |

事实沿用现有 `position` / `artifact` 信封。对图像、点云、检测、占据、关节状态和规划场景分别定义版本化载荷。派生事实记录上游引用及生产 binding。空间融合还需给出同步窗口、TF 采样与标定版本、覆盖范围、不确定度和缺源。缺少可选输入时，按契约给出覆盖降低后的结果；失去必需输入时返回缺失原因。不同主体的同名 `map`、不同高度基准或不同时间的点不能直接拼接。

区分**单次读取**与**持续生产**。检测截图可以按需执行。需要连续观测的跟踪、融合和建图由独立服务持有订阅、缓存、状态代次和检查点。站点声明频率、最大队列、延迟、过载时的丢帧规则和 GPU 预算。Agent 读取有时效的快照或订阅事件。图像、点云、地图经制品引用传递，任务账本保留摘要与小型结构化结果。地图发布或切换活动地图属于独立的状态变更，采用相应的写权限和版本回执。

### 3. 将自然语言组织成可验证的任务

在现有步骤协议旁增加可选的类型化结果引用。用户图和 Agent 生成的图采用同一执行语义。节点引用能力版本、参数或上游输出端口。一个节点可消费多个结果，一项事实可供多个节点复用。第一版支持有界的有向无环图、并行独立节点及基于结构化结果的条件分支。持续监听交给上节的状态服务。已有顺序步骤保持有效。

任务入账时保存**目标、主体、必需输出和成功条件**。调度器校验端口语义与版本、作用域、效果、时间和资源上限，形成冻结计划。执行中将真实输出引用交给下游；重试复用原操作身份，取消传播到已派发节点，已完成且仍有效的结果可跨分支复用。重规划只改动受影响的未派发部分，产生新 revision 并指回父计划。所需结果缺失时，报告已取得什么、还缺什么。单个工具成功回执只证明该步骤完成。

例如，复核节点的输入端口可声明为“本次任务 `measure` 节点返回的 `regions`，符合区域深度统计 v1”。调度器从已验证回执取值，检查同一主体、帧与统计方法，并固定内容摘要。距离、列数等用户指定条件保留在任务目标里，与调用参数和最终证据分别比对。选择错能力导致的假成功用留出的自然语言正反例测试；影响结果的单位、目标或参考系有歧义时，前端展示待确认项。

**例子。** 对“只看一米内，告诉我先复核哪边”，站点若已有合格的用户 workflow，Agent 可以一次调用并直接核验“优先区域、距离证据、未知区域”。也可以按本次输入将对齐深度、分区统计及复核排序组合起来。若后续目标改成“为底盘预览绕行路线”，解析器另需底盘可用的占据或障碍表示、定位、地图及足迹。在只有相机列深度的情况下，前端保留复核结果，列出无法规划所缺的输入。

### 4. 规划层按主体能力与产物分型

任务层决定“要得到什么”；领域规划 Provider 计算“在当前机型和约束下有哪些候选”；独立验证器判定候选满足哪些约束。规划的交付物是一份可显示、验证和回放的计划制品。它的生成、审核和获授权的实际执行由不同接口承接。

建议新增共用的计划制品头，包含主体及资源引用、能力与输出 schema、目标和约束摘要、输入世界快照、机体模型和工具版本、有效条件、验证结论及制品摘要。载荷按领域独立演进。

| 主体与问题 | 规划输入 | 专用产物与验收 |
|---|---|---|
| 差速、阿克曼、全向底盘到达地点 | 平面地图版本、定位、足迹、运动学和局部障碍 | 地面路径。分别验证膨胀后净空、最小转弯半径或相应运动约束。可包装现有路线或对接 Nav2 只计算路径的接口。 |
| 无人机到达观测区域 | 三维占据、位置和高度基准、机体包络、批准空域、速度与加速度限制 | 空间航路或带时间的飞行轨迹，按声明验证。只有几何折线时，仅返回航路级结论。 |
| 机械臂到达抓取预备姿态 | 模型和关节组、当前关节状态、末端工具标定、目标位姿、场景与碰撞体版本 | 关节路径或定时关节轨迹。验收检查逆解、关节限位、自碰撞及环境碰撞，并按需检查时序约束。MoveIt 可作为候选后端。 |
| 四足机器人或人携带终端到达同一地点 | 可通行地形与步态能力，或步行网络、楼梯及无障碍要求 | 前者返回地形路线或足步计划，后者返回人可读指引；各自采用相应的到达或送达条件。 |
| 移动机械臂处理工位目标 | 同一 actor 下的底盘与机械臂资源，衔接姿态、共享场景版本、空间占用 | 可先分别试算，再检查底盘终点处的机械臂可达性及整机碰撞。需要同步运动时选择有整机能力的提供者。 |

站点用主体 profile 声明它有哪些可寻址资源、运动模型、传感器、规划能力和验证器。站点可同时保存多个地图及算法，计划通过显式地图身份、修订和定位代次选用。活动地图变化、重新定位、关节初态漂移或动态障碍更新，都按产物的有效条件触发复核。相同目标允许不同机器人选择不同实现，无法表达约束的后端会留下可读的拒绝理由。Nav2 路径计算和 MoveIt 规划流水线的公开接口可分别作为底盘、机械臂的接入参考。[Nav2 路径计算](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/bt_plugins/actions/ComputePathToPose/) · [MoveIt 规划流水线](https://moveit.picknik.ai/main/doc/examples/motion_planning_pipeline/motion_planning_pipeline_tutorial.html)

### 5. 权限、生命周期和可见性

- 自动创作的权限取任务授权、站点策略、依赖能力与部署沙箱的交集。已批准的只读工具组合可直接执行。新受限程序须通过独立样例、资源上限和效果核验后才可热装。通用用户代码和模型生成的任意可执行代码使用独立受控进程与相应审批。新增 ROS 桥、设备挂载、框架或底层控制变更走部署审查。
- 只读桥仅取得明确的数据或规划服务权限。已有 ROS 进程若同时暴露运动命令端点，部署时须能验证桥实际可达的接口和 ROS 身份。包含控制路径的第三方 workflow 在规划站点拒绝准入。需要运动时由 Body Runtime 单独接收引用、重新检查现场事实和授权，持有独占资源、租约、原操作账本与独立见证。各机型定义相应的安全交接条件。[DSH 物理轨](../plugin-descriptor-v2.md) · [Body Runtime 基线](SDD-050-body-runtime.md)
- 纯软件版本切换让新请求使用新绑定；在途读取依原版的冻结与排空协议结束。具状态的服务显式迁移或开启新代次。失联的物理操作沿原 ID 对账，结果未知保留恢复状态。停用一个候选仅影响依赖它的工作。
- Console 按实际事件展示原任务、预期输出、选中 Provider 及来源、实际组合、输入时刻、已排除候选的可公开理由、缺测、计划有效条件与验证结果。明确区分“人工复核建议”“路线/轨迹预览”“执行回执”。私有 workflow 只显示它发布的证据。旧任务按原 binding、工件与时间回放。

## 验收与证据

以下条件用于分阶段验收。本轮实测的任务范围与原始记录导出方式见[感知对照验收](../testing/rgbd-review-comparison.md)。

| 编号 | 实验与通过条件 |
|---|---|
| AC-1 | 在相同 RGB-D 录包上，用内置实现、用户 workflow、Agent 临时组合和 ROS 回放适配实现同一复核请求。对颜色/深度配对、未知区、优先顺序分别使用独立标签和预定容差。新用户实现只增加插件包和站点声明。 |
| AC-2 | 同时安装两种可满足目标的算法和一种语义不兼容的算法。停用首选实现后，新任务选择可用备选，已冻结任务可追溯到原绑定。相同 DSH 导出名冲突被拒绝。某个备选离线不阻断无关任务。 |
| AC-3 | 让数值工具成功但遗漏“优先复核区域”，任务验收必须报告未满足目标。再注入陈旧 TF、主传感器缺失、跨时钟错配及 GPU 超时，检查每种恢复或拒绝的原因与真实回执。 |
| AC-4 | 同一场地配置两个地图版本和两个主体；跨主体、过期地图和定位代次错配会拒绝。移动机械臂示例中，底盘可达但机械臂超限时，组合任务不能整体通过。 |
| AC-5 | 在隔离环境给车、无人机和机械臂分别提交规划请求，检查各自产物 schema 与独立几何/运动学验证器。记录真实后端或夹具身份，监测运动、解锁、执行轨迹等命令计数均为零。 |
| AC-6 | 用用户工作流尝试访问未声明端点或控制资源，检查站点准入及实际进程边界。录制中断、服务重启、算法排空及取消后，按原 ID 恢复，能明确哪些节点完成、失效或待核对。 |

## 迁移与回退

1. **P0，感知可替换。** 将当前深度筛查和另一个用户实现映射到同一语义契约，提供只读目录视图与按结果验收。延续现有 Tool 名、站点绑定与历史任务。先用相同录包验收，再在 Jetson 上做静止只读复核。
2. **P1，组合可复用。** 为只读计划增加类型化结果引用、预算和局部重规划。用用户图与 Agent 生成的不同图实现两个真实任务。将作者族和验收器迁到受信站点注册，绑定精确的族版本与程序身份。通过后才开放候选创作。
3. **P2，规划跨构型。** 先用现有地面路线包装第一个规划产物，保留 `nav_plan`、`route_ref` 及其原校验。分别接入地面第二算法、飞行三维规划及机械臂规划后端，验证移动机械臂的组合目标。先录包或仿真，然后按机型单独开展只读真机验收。实体执行另立范围。

各阶段由可选站点 pack/profile 开启。回退时先停止新准入，排空受影响插件并保留旧 binding、计划和工件，再切回上一站点锁。已派发任务按原版本恢复。真实机型能力与验收环境分别记录。

## 变更记录

2026-11-23，针对真实分区复核试验及多构型规划需求提出设计。核对 DSH 描述符、只读创作、空间观测、任务步骤及路线源码，定义 AC-1 至 AC-6。本轮交付为规格草案。

同日，在 Jetson 上部署独立的只读 DSH 站点。对同一录制 RGB-D 帧，独立工作流示例、车端模型临时组合、内置实现及排空后的备用实现先后完成四次同文请求。站点工作流通过独立进程加载，模型在组合任务中选择带类型的原子服务。原始像素独立复算、模型响应与节点回执核对、停用前后策略摘要比对均通过。AC-1 已覆盖这三类软件来源，AC-2 已现场验证新任务切换及历史回执冻结，本地注册表测试覆盖在途读取；实际 ROS 算法替换、复杂有向图和机型规划留待后续。结果详见[实测与重放](../testing/rgbd-review-comparison.md)。
