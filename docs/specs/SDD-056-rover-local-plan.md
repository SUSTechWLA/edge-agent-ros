# SDD-056 轮式底盘前向障碍观测与局部规划

## 背景与价值

单机 Gateway 已能沿授权目标前进、检查前方激光覆盖并制动。校园局部导航需要在有静态障碍时衡量可用空间，并用独立的世界轨迹复核避让。第一轮只覆盖轮式车、本地模拟激光、短程点目标，以及 clear 和 centered 两种 Gazebo 场景。

## 设计与契约

现场只读工具 `preview_rover_obstacle_path` 消费车体坐标系中的观测与站点足迹，记录开始和结束时的实测位姿，并把局部路径投影到里程计坐标系。位姿缺失时只输出车体坐标。结果分别报告相对已知表面的净距与沿途观测覆盖。每次采样关联原操作 ID，重试读取原收据。工具容器只访问观测服务。v1.0 的历史回执保留当时计算的折线。

### 可复用的轮式车局部路径能力

常驻软件提供者接收机型、带采样时刻的车体观测和短程子目标，返回候选路径及其观测覆盖。Agent 的 Tool 入口额外负责自然语言任务所需的取样和持久化。软件消费者使用独立的单帧评估入口。两个入口复用同一几何实现。单帧评估跳过模型、跨帧取样及操作账本。感知提供者负责观测身份和标定，探索策略负责选择前沿，全局路由负责把下一段目标变换到本地，物理执行所有者负责运动授权、跟踪和制动。

| 验收项 | 可检查的结果 |
|---|---|
| 平滑与净距 | 候选曲线按实际切向摆放矩形车身。对整段检查扫掠净距与曲率上限，采样间隙计入裕度。路径的起点、横向过渡和终点连续。前端按提供者返回的几何取点绘制。 |
| 输入与降级 | 坐标、时间、标定、边界或机型不适用时拒绝评估。未知区域影响覆盖等级。起点净距不足返回保持原位，路径为空。动态预测需要带时间的目标轨迹与对应算法，静态结果仅表达采样时刻的观测。 |
| 扩展与绑定 | 使用明确的局部子目标复用同一个 Service。实现和车体参数由站点版本管理。在途任务重试查询原操作。新版本的规划结果须有可追溯的算法和约束。 |
| 计算与时效 | 机器入口限制并发、输入预算与数据年龄。忙或过期时立即拒绝。分别测量算法、同步请求和任务收据的耗时。50 ms 是现有 Gateway 的调度周期，适配器还须计入传感器、传输和执行延迟。 |

该几何契约适用于前向平面轮式运动。车辆速度、加速度、转向执行器动态和制动决定随时间的舒适性。飞行器、机械臂分别需要三维运动学和关节空间的轨迹提供者。实际运动接线继续遵循本规格的物理绑定、独占与停车验收。

决策 A。在 Gateway 现有 50 ms 循环内调用无 ROS 依赖的 LocalPlannerPort。默认 StopOnClearance 保留既有方向控制、速度上限和扫描覆盖检查。GapFollow 为站点显式选择，只处理当前授权操作。算法提供候选输入，Gateway 经停车、心跳和独占检查后向现有速度或 Body Runtime 入口输出。Core 维持 1–8 个 ±4 m 路点、原 operation_id 和到达后新里程计 ≤0.12 m 的验收。

只读 FrontObstacleReport v1 绑定来源、frame、源采样时戳、序号、有效性及原因、标定身份。报告以米、弧度给出最近可见表面的距离、方位、可见宽度、前/左/右距离、左右可用宽度，带相对接近速度和 TTC。射线未知、无返回、没有接近与无法估计的情况显式区分。规划同时消费连续可见空间或经校验的同帧射线；两个宽度数值不足以独立推断扫掠安全。接口可由有车体标定和时钟证据的其他只读来源实现。此轮未验证 D435/Livox。

局部决策包含 decision、linear_mps、angular_radps、clearance_m、ttc_s、reason_code、report_ref。同一操作中的多拍复用原采样序号。现有 0.42 m 激光前进硬停保留；GapFollow 按车体轮廓预留 0.55 m。无安全通道、TTC 不足、扫描或定位陈旧时执行停车。独立停车证据不足时仍需 RECOVERY_REQUIRED。事件 perception.front_obstacle、navigation.local_plan、navigation.local_stop、navigation.local_avoid 复用 task、trace、operation 关联。报告是观测事实，决策是建议，运动副作用仍归原执行所有者。

### 提供者与消费者

- 本轮提供者将校园水平激光投影到 `base_link`。Gateway 在选择 `gap_follow` 时发布 `/edge/perception/front_obstacle`（`std_msgs/String`，JSON v1）。只读消费者可使用报告中的测量和来源。进程内的规划器还使用同一次扫描的完整射线，运动扫掠要求全周覆盖。单个前置相机接入时，需要补齐经过标定的可见空间，或者实现适合该视场的规划器。
- `GapFollow` 用这台轮式车的 0.31 m 圆形包络评估候选通道。目标方向受阻时，沿两侧搜索能维持强制净距的方向。已选侧优先，两侧均无解时返回 `navigation.no_safe_path`。同一份报告可供多个控制周期使用。首次无法估计接近速度时等待新扫描，可确认碰撞时间低于 0.8 s 时停车。该设计的验收对象是静态障碍。
- `LocalPlannerPort` 是编译期 C++ 扩展接口。调用方只向它传入观测与目标，算法返回建议。Gateway 持有速度输出权，Core 持有路点账本与独立到达判据。算法、车体尺寸或标定的更新按物理 Runtime 的停机交接处理。只读报告可独立订阅，本轮仿真实现随 Gateway 部署。多源融合、运行时装卸感知提供者、其他机型均需后续验证。

## 验收与证据

### 灵遨机型的局部绕障

以现场归档的 `lingao_mid360.urdf.xacro` 为机型依据。足迹围绕四轮中心定义，以米分别记录前悬、后悬和两侧外缘。选择机型规划器时显式绑定尺寸、轮距和模型来源。四轮左右同速组成差速驱动，采用与此底盘相容的前进、转向和制动命令。规划检查整车在候选方向和实际转动过程中的扫掠空间，保留传感器未知即停车、0.42 m 前向硬停、0.55 m 规划预留与 0.45 m 独立验收下限。优先比较在相同车体、传感器、起点、目标、静态箱体上，变更前后的最大横向偏移、行驶距离和实际车身净距。将仿真轮胎、传感器、附加尺寸和未经实测的动力学假设与归档实测尺寸一并列入验收记录。

方法参考公开自动驾驶规划中“障碍物外缘、自车宽度、横向余量”分别计量的设计。对灵遨车，用归档机型矩形的方向投影表达宽度和悬伸，用差速运动学检查圆弧、转动与制动。每次任务开始的 Gateway 事件记录已加载的实际尺寸，每个局部决策关联同一机型版本。[Autoware 静态障碍绕行的横移量计算](https://autowarefoundation.github.io/autoware_universe/main/planning/behavior_path_planner/autoware_behavior_path_static_obstacle_avoidance_module/#shift-length-calculation)

- AC-1：无 ROS 单测验证几何、来源、时间、非法覆盖、两侧候选、对称与窄缝、TTC、移除恢复和限幅；回归既有默认控制与停车接口。
- AC-2：同一校园场地、起姿与目标，clear 无假避让并到达。centered 新增一只 0.5 × 0.5 × 1.0 m 静态方箱，要求有与操作关联的避让事件、可观测轨迹绕行并到达。
- AC-3：用 /ground_truth、碰撞几何和执行时障碍位姿核对表面净距 ≥0.45 m、到达误差 ≤0.12 m、无非地面障碍接触。障碍距离误差 ≤max(0.05 m, 真值×5%)、方位 ≤2°，正常避让期间无 0.42 m 硬停。报告保留失败样本及原事件序号。
- AC-4：六组扩展场景、ARM64 和台架均留待下一轮。此次两个仿真场景不构成发布门。

## 迁移与回退

### 自然语言发起的有界避让与动态扩展

操作者通过标准 `POST /agent/tasks` 提交原句「躲避前方障碍物」。部署站点独立授予本次仿真机体的操作权限，模型从可用能力目录选择工具。模型无法指定轮速、传感器证据或世界坐标。未给目的地时，物理提供者基于本体姿态、当前前向报告和站点允许的通过距离冻结一个短程目标。已清空时凭新鲜观测结束；未知、定位不合格或已有目标持有执行权时保留原操作。软件插件可组合观测和规划，物理执行经独占租约、Core、Gateway 以及独立核验结算。

动态观测和让行策略可分别替换。首个实现以 `dynamic_observer:=scan_clusters` 和 `dynamic_policy:=yield_crossing` 显式启用，只接收带时间与坐标系的扫描、里程计。动态事实经 `/edge/perception/dynamic_obstacles` 提供给其他插件；让行、通道恢复用 `navigation.dynamic_yield`、`navigation.dynamic_clear` 关联同一操作。等候时停车，直到新鲜扫描证明通道恢复。原硬停与输入过期停车优先。更换物理策略需停止接单、结算和见证停稳。

仿真验收从 Agent HTTP 入口发起同一句命令，在静态方箱与横穿物体场景记录真实模型选择、物理绑定、Core 路点及验证。独立见证者仅用于评分，依据世界位姿、轮廓及接触计算净距、终点误差和停稳；动态物体必须真实横穿，车须在冲突区前停车，物体移出后原操作恢复。现场验收另需实测附件外廓、传感器投影和时钟、定位、唯一底盘命令所有者、实测制动距离及独立停车证据。

感知与算法选择由部署配置控制；运动算法的变更须先停止接单、结算原操作、见证停车，再重新启动 Gateway。回退选择 StopOnClearance 或原固定版本镜像，核对单一输出者、旧操作记录与 Core 到达验收。用户授权的 G1 分支独立于 P0、历史现场插件和当前 Jetson。
