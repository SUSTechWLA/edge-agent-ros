# SDD-030 校园中四种机体的 Edge Agent 闭环

## 背景与价值

校园需要验证不同形态的机器人如何接收同一种自然语言入口、发现自己的专用工具、驱动执行器并拿到真实观测。仅将模型摆进场景无法证明任务成功。先在本地 Docker 的同一座 Gazebo 校园完成可重复的单机体能力实验。

## 设计与契约

校园中可见轮式车、四旋翼、四足与双足机体。优先使用授权明确的常见参考机型，记录原厂数据、简化动力学、固定支撑及传感器的区别。每台可执行机体具有独立标识、作用范围、控制输入及时间戳明确的状态。通过现有 Agent 任务/工具扩展点下发任务。执行方只能在相应机器人专用接口发动作。验收方根据新鲜的关节、姿态、位置或传感器测量验证结果，保留任务、调用与观测证据。

## 验收与证据

| 编号 | 观察或实测 |
|---|---|
| AC-1 | 在同一场景能辨认四种机体，地图能定位/查看机器人，各自传感器从明确的 ROS 或 Gazebo 话题产生真实消息。 |
| AC-2 | 每种机体至少一个自然语言任务经 Agent 和工具到达仿真执行器。记录动作前、动作后物理反馈与通过判据。 |
| AC-3 | 能区分车导航、多旋翼高度变化、腿式或人形机器人的关节任务。说明是否验证自由步行、平衡或飞控，以及测量用何参考坐标。 |
| AC-4 | 隔离实例执行测试，验证目标别名/跨机体路由、无反馈/不支持动作时的失败以及与校园既有导航任务兼容。 |

## 迁移与回退

新能力按场景与插件接入，可移除对应配置并撤下独立提供者。保留既有小世界、任务记录以及运动网关的权限边界。
