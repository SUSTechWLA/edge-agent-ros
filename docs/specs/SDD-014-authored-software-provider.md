# SDD-014 · 从插件设计生成可运行的纯软件 HTTP Tool

## 背景与价值

SDD-012 可以组合数列算子，SDD-013 可以输出新插件设计。为了让“忽略大小写，统计文本中单词 robot 出现几次”经过同一研发流程，需要把编码 Agent 的候选与设计关联，独立检验输出，再由获准的发布者把它提供给已有 Agent。

## 设计与契约

复用 HTTP read Tool、ModuleJournal、发布锁、CAS、旧版存档与发布收据。候选为 `def transform(text)` 的单个返回表达式，支持有限的字符串与词列表方法。独立 HTTP Provider 在限额容器内解释经核验的 AST，接收操作 ID、版本和文本，只读计算；请求体、文本及结果均有上限。Provider 自身、候选、语义清单参与版本摘要。候选可由编码 Agent 提供或本地 Ollama 生成。私有候选源码、测试集与部署收据保留，公开事件仅引用版本、来源、数量、摘要和原因码。

发布者查验真实 `plugin.design.drafted` 事件、草案摘要和 task/trace，验证独立期望（部署方提供），持有发布目录写权限的操作者显式指定批准的版本。接受请求、验收失败、发布、撤回均有证据。Tool 运行无宿主目录写权限、无 Docker 套接字、无设备权限。适用范围限于单机部署中的纯文本计算。

Tool 自选 `verbatim_argument: true` 和一条带首尾边界、单占位符的 utterance，例如 `统计 robot 词频【{text}】`。参数必须是单个 string。Agent 按任务原文逐字符提取边界中的正文，保留全半角、尾部标点、空白和空串；规划器校验模型给出的参数与原文相同。既有工具继续沿用自己的参数契约。发布者以部署端配置的 Console 重新读取设计事件并比对来源。批准摘要绑定私有设计及其来源事件、候选与宿主摘要、独立验收样本和最终清单，改变其中任何一项后须重新验收、批准。

## 验收与证据

- AC-1 使用 SDD-013 格式的真实草案与事件生成或导入候选，内容改变后旧摘要失效。样本包含重复单词、大小写、空文本和仅含目标子串的词。
- AC-2 无效语法、越界输入、未支持的表达式、错版本或错误样本明确拒绝。发布前清单缺席，失败不授予执行权。
- AC-3 通过公开 Agent API 验证安装前受阻、安装后成功、卸载后新任务受阻；旧任务可读，以相同 trigger 重投不产生第二次调用，Agent 进程身份保持。
- AC-4 样本、源码、语义清单、提供者实现、设计和 trace 可定位，重复发布遵循请求 ID，错误期望版本保留拒绝；已有清单不能被静默覆盖。
- AC-5 同时接收至多 4 个请求，每个连接从接收到关闭最多 5 秒。其余槽位可服务正常任务。发布器对设计归档与单个样本各设 5 秒总预算，对整批样本设 15 秒预算，对本地模型设 120 秒预算。超时或传输中断需留存原因，不能改变活动清单。以旧版摘要请求卸载时须保留新版。调用方核对操作、版本、输入摘要和非空值，算法本身由批准的实现和独立样本验证。

## 迁移与回退

以独立容器启动候选，完成隔离验收后注册；先确认当前绑定与活跃操作，再按现行注册内容摘要撤回。需要旧实现时恢复对应候选、镜像和语义配置并重跑样本。中间失败由发布器的持久意图与下一次发布对账。撤清单不应删除已保存的研发工件或执行历史。
