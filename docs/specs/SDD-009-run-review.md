# SDD-009 面向值班人员的运行复盘

## 背景与价值

机器人空闲半小时以后，打开观测台的事件记录，最近 30 条可能全是周期采样。值班人员想知道“现在在做什么，上一次做成了什么，哪一步出了问题”，原先需要猜任务 ID、翻页再对照账本。日常仿真中已有 52 个语言任务，既有完成的巡检也有因路径被挡而阻塞的任务。一次测到的位姿能帮人判断机器人当时在哪里，任务账本和动作回执才能说明为什么停下。

## 设计与契约

- 观测台增加只读「运行复盘」。显示实时运行状态、任务结果、已记录的系统变化和历史问题。任务详情可以直接用地址打开；进入回放应明确显示回放时间。首页、原始事件和自动化订阅继续可用。
- Agent 持有语言任务的原文、状态和步骤。Console 从既有 SQLite 任务表读取分页目录；按全部、活动、成功和异常分类，计数覆盖整个账本。接口为 `GET /api/review/tasks?state=all|active|succeeded|issues&before=<游标>&limit=N`，返回 `tasks,counts,next_before`。每项有 `id,text,state,detail,created,updated,trace_id`。数据库不可用要单独报告，避免把读失败展示成零任务。
- Console 的历史归档持有已经采集的公开事件。给原有 `/api/events` 增加可选 `view=changes|issues`，在数据库分页前筛选。变化视图跳过普通周期快照，保留可诊断事件及新模块自定义事件。问题视图呈现历史诊断；一条历史告警不能单独证明问题现在仍持续。无筛选查询、导出和按编号回放保留原行为。
- 从一项任务进入过程，显示当前账本结果及按时间排列的已记录事实，再按需要展开事件编号、诊断、相关操作和前因。以 task_id 定位一次工作，trace_id 可串联后续工作，operation_id 定位具体动作。Console 的 session_id 表示观测进程的一次运行，重启后仍可沿同一任务回溯。
- 本次读取已有任务和事件。前端展示仅使用现有公开接口；证据缺失、服务断连和任务尚在执行分别呈现，不从快照推断故障根因。阅读、筛选、导出和回放不派发任务，也不重试机器人动作。

## 验收与证据

| 编号 | 输入和操作 | 可观察的验收结果 |
|---|---|---|
| AC-1 | 已完成、活动和受阻任务混合；切换分类并翻页；任务库暂不可读 | 可从目标文本找到任务，全局计数稳定；游标无重复；断连提示独立于空结果。 |
| AC-2 | 在状态变化或异常后记录多于一页的普通快照 | 人仍能找到变化与问题；原始查询和采样事件的回放可用；不同模块发出的同名异常得到保留。 |
| AC-3 | 打开已成功、受阻或缺少证据的任务 | 分别看到实际结果、源事件诊断或证据不足；能够核对相关的事件详情、回放和导出；可用深链接重新打开。 |
| AC-4 | 在桌面及手机宽度从原界面打开复盘并返回 | 当前与历史文字和时间可辨，能从任务读到证据；既有地图、事件筛选和任务入口可用。 |
| AC-5 | 更新日常观测台并核对原任务、归档和运行服务 | 只重新创建 Console，既有任务 ID、状态与归档身份保持可读。独立环境做功能和界面测试，日常环境做只读验收。 |

## 迁移与回退

本次升级不迁移任务表和事件归档。通过 Compose 只更新 console 服务，核对原任务结果、历史事件号及归档身份。回退时以此前镜像执行同一服务更新，继续挂载原命名卷。
