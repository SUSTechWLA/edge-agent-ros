# SDD-007 单 Edge 的模块事件总线与插件变更证据

## 背景与价值

从 738172a 的一次失败任务出发，开发者已经可以看到规划、模型和工具交换、操作编号、重试以及独立验收回执。但是空闲时将验收插件从 v1 切到 v2 再退回 v1，只看当前目录会误判为从未升级。作者的候选、发布者的本地历史、Agent 的服务目录和 Console 的任务归档分别回答不同问题。需要让新人和诊断 Agent 能够查出谁观察到了什么、依据是什么、证据在哪里、还有哪些结论未知。

## 设计与契约

单机复用现有事件 v1、SQLite、只读归档 API、事件消费者和任务所有者。关键模块可以持有各自的本地持久事件源。Console 逐源按序导入已提交的事实，保留生产者事件 ID、父 ID、trace、来源和发生时间。全局序号表示收录位置。历史回放只用于复查；实际执行仍经过原有授权、版本绑定和操作幂等检查。普通传感器样本仍适用保留策略。

第一期接入三种事实：运行时服务目录实际观察到的变化；作者根据任务失败形成的候选、拒绝或延后；受管声明工具发布与移除的意图和核对结果。三种事实有各自的发布主体与命名空间。它们可以独立出现。没有调用证据时，不能从已发布推断某个任务已使用新插件。文件观察依据实际采样，禁止回填两次采样之间的推测。无法将文件变更归因到确切写入者时记录可核实的状态与不确定性。

每个关键事件须有稳定身份和类型化诊断码。重复导入不重复生成事实；同 ID 异内容和不合法输入必须可诊断。无任务的运维事件允许缺少 task_id。业务状态与其本地证据尽量同事务；跨文件或服务的变更采用先写意图、事后对账。禁止归档凭据、原始候选提示和私有服务地址。新增模块应说明自己的责任、事件 schema、失败窗口、重放方式和副作用权限。

## 验收与证据

| 编号 | 故障或输入 | 判据 |
|---|---|---|
| AC-1 | 服务安装、停止接新工作、换版、失效、恢复原版本、移除；反复读取同一目录 | 仅可观察变化生成事件，保留前后状态、版本或诊断码；相同状态再次出现仍可区分；不生成任务。 |
| AC-2 | 停 Console 后连续变更；重启 Agent 与 Console；重启只读订阅者 | 源中已提交事件可补录，保持原 ID、来源顺序和因果链；消费者重放不重新执行设备操作。 |
| AC-3 | 失败任务触发作者；重复交付、已写回执后崩溃、模型暂不可达 | 候选/拒绝/延后有持久证据并关联原始事件；同一决定不重复，公开信息不含原始模型输入输出。 |
| AC-4 | 受管发布、冲突、撤回，进程在文件替换与回执之间退出 | 能区分请求、实际响应和待核对状态，有前后内容版本、测试摘要与因果 ID；恢复时不猜测写入者。 |
| AC-5 | 重复、冲突、损坏、父事件晚到或归档重建 | 重复不会污染序号；问题源不能阻塞其他源；可能缺失的父因保留 ID；重建不改生产者 ID。 |
| AC-6 | 原有任务和观测、部署和仿真回归 | 明列执行的命令、镜像、环境、实测结果和范围；真机及外部未接入进程单列。 |

## 迁移与回退

升级后首次观察现有描述符建立基线。保留已有任务库、归档和插件目录；保持 /api/events 与现有消费者的契约。回退到上一版本可继续读取旧任务，保留新增证据和源卷供导出。升级不能复原旧版运行期间未被记录的变更。
