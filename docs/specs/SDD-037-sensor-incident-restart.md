# SDD-037 巡检进程重启后续查未结束的故障

## 背景与价值

在 1.0.0 的巡检插件中，Docker 可以重启崩溃的订阅进程，但每个输入重新进入等待状态。故障前的两条恢复样本、旧告警是否真的消失、进程停机时发生了什么，操作者都无法仅从新进程的“正常”回答分辨。需要保留未结束事故，并要求重启后重新积累恢复证据。

## 设计与契约

传感器插件在自己的 SQLite 库中保留每个输入一个未结束事件指针。状态转换和指针更新在同一事务内完成。输入身份由本模块的事件源、机器人配置、ROS 域、仿真或设备时间、输入种类、话题和期望坐标系组成。启动时复核身份并给续查事件写入上一条事件 ID。停机间隔没有观测，新的采样计数、复核计时及 HTTP 最近样本从本次启动开始。相机实际 frame 可在没有指定 frame 时协助识别来源更换。已经关闭、配置变化或移除的输入不继承旧告警。旧版只写公共事件，缺少足以确认同一台机器的身份指纹，升级后保留原始归档，旧记录的空窗留给操作者核查。

## 验收与证据

| 编号 | 实验与通过条件 |
|---|---|
| AC-1 | 在独立 Docker 实例将正常 ROS 图像切换成持续黑图，记录 `needs_attention` 的事件 ID。终止进程，Docker 依 `unless-stopped` 自行重新启动同一容器。 |
| AC-2 | 新进程保留前次告警与可追踪父事件引用，停机空窗明确。再次收到黑图后仍需关注。恢复第 1、2 份新鲜独立样本时维持告警，收到第 3 份才产生恢复事件。 |
| AC-3 | 已关闭的告警不会在再次重启时复活。更换机体、话题、坐标配置或 ROS 域的实例开启自己的观测，保留旧记录，不跨源确认恢复。 |
| AC-4 | 部署者显式 `docker stop` 后进程保持停止。恢复试验不向校园日常 ROS 域或真机发送数据。 |

## 迁移与回退

沿用已挂载的模块卷，启动时新增插件私有表。1.1.0 将同一库的写入者限定为一个进程。部署时为物理机体配置稳定且唯一的 `EDGE_HEALTH_ROBOT_ID`。校园默认 `edge_rover`，硬件工程继承 `EDGE_ROBOT_ID`。回退 1.0.0 前保存归档，旧程序不理解新增恢复指针。如在降级运行后再升级，使用新卷建立新观测来源并保留旧归档，以免恢复指针越过旧程序的运行窗口。
