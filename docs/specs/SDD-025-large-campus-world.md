# SDD-025 · 可独立安装的大型校园仿真场景

## 背景与价值

原有工坊与庭院适合快速测试穿门和停车。校园实验还需要远距离视线、林下遮挡、车道边界、室内外切换以及大面积开阔地。把大型素材直接装入默认世界会抬高每次开发回归的成本。

## 设计与契约

校园作为独立的仿真环境插件。下载固定版本的公开校园资产，记录作者、许可、上游地址、字节数与校验和，在本地持久缓存。按需补充仿真教学室内、树林、运动场和草坪，明确上游与本项目各自提供的内容。校园启动后使用本地文件。离线构建器从资产与场景定义生成 Gazebo 世界和对应的场地信息。沿用现有机器人模型、时钟、里程计、激光与任务契约。独立 Compose 工程、网络、端口和卷把它与日常小场景分开。

## 验收与证据

- AC-1 首次下载得到真实校园资源；核对校验和、许可与实际网格。已缓存时断网可启动，缺少资源时在生成阶段指出恢复命令。
- AC-2 在 Gazebo Harmonic 中载入建筑、可通过的教学楼室内与门口、成片树木、车道、运动场和草坪。记录米制尺寸、空间位置和室内外实测示例，提供可供使用者辨认各处的总览。
- AC-3 真实 ROS 订阅读取持续更新的时钟和机器人观测，短程跨门验收有里程计与结果证据。场地的总范围和当前工具获准执行的运动范围分别说明。
- AC-4 校园可独立启动、停止与重开。原有任务系统、默认小世界与感知回归继续按原契约运行。用差异清单与独立服务状态核对插件边界。
- AC-5 总览、建筑、门厅、运动场、林地、车道和草坪各从 Gazebo Transport 取得一张现场图。快照保留采样时间与世界版本，收到后释放订阅。界面在图像到达前显示等待状态，世界发生变化时重新取图。
- AC-6 校园热重载会重建仿真时钟基线。先从公开接口检查活跃任务、底盘任务、动作与停车证据，关闭校园 Agent 的新任务入口后再检查一次。有在途工作、无法验证结果或机器人仍在运动时说明原因并保留原世界。重载时停止所有运行中的校园时钟消费者，保留任务卷与历史，再启动各层；新任务应能得到新时间段的 ROS 回执。

## 迁移与回退

通过单独的 Compose 文件和工程名启动。校园数据、默认工作台和已有任务账本分别持有。撤下校园工程后，本地缓存可供再次启动。
