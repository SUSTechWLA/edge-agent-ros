# SDD-002 · 从门内工位到室外庭院

## 背景与价值

占用格能表示自由、障碍或未知，却无法告诉任务代理“庭院在哪里”。一个有墙、有门、有室外设施的测试场地能把语义解释、路线选择和实际通过门口这三项能力分别验收。

## 设计与契约

用版本化场景标注声明区域、地标、通行点及连接，生成 Gazebo 几何。传感器独立观测实际世界。可替换的场景插件发布带 frame、版本和来源的 ROS 语义层，并以语义目标能力响应巡检。规划依据有足够间隙的连接图，拒绝隔离区及未知地点。运行中的前向激光可发现实际阻挡，将原因交给事件和任务链。历史回放使用当时的地图与位姿。

## 验收与证据

- AC-1 浏览器可区分室内、门口、室外、地标及传感器观测，能查看机器人当前所在区域与标注来源。
- AC-2 从室内向有名称的庭院下发自然语言任务并反向返回；独立 Gazebo 位姿证明穿过门口、到达目标。
- AC-3 对未知和不可达地标返回稳定原因；对直驶向实体墙体的委托检测激光阻挡、停止并可回溯。
- AC-4 旧场景、无语义发布者及旧历史仍可展示原始观测，开发者能替换地图提供者。

| 条件 | 证据与复测方法 |
|---|---|
| AC-1 | [仿真工作台画面与图例](../semantic-scene.md)区分场景先验、融合位姿、激光、占用格和独立仿真真值。 |
| AC-2 | 在起点为工位的空闲仿真执行 `python tests/semantic_acceptance.py`。实际去庭院与返回工位终点误差约 0.065 m、0.048 m，验收阈值 0.18 m。门口分别捕获到 9 和 8 个独立世界位姿样本。[逐任务证据](../evidence/semantic-sample.json) |
| AC-3 | 同一脚本用未知地点、维修区和面前的供测墙体验证拒绝原因及位移。对实体墙的直接请求在世界坐标 x≈1.29 m 处制动，之后能够执行返程。 |
| AC-4 | [部署与地图替换步骤](../semantic-scene.md)；几何、图连通性和新旧控制台历史分别由 `tests/test_scene_layout.py` 和 `console/server/test_replay.py` 验证。物理板、未知场景建图和自主绕行需要各自的现场或算法验收。 |

## 迁移与回退

默认仿真采用混合场地；保留原有空场 SDF。语义模块通过 ROS 和技能协议接入，真实设备需提供与定位结果对齐的标注及导航适配。仿真世界改变后重新定位并开启新的仿真会话，历史任务留在原卷。
