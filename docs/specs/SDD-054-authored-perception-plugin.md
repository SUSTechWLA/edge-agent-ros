# SDD-054 在只读站点创作并复用独立的感知插件

## 背景与价值

现场已有 RGB-D 分区读数，但单个读数不能回答“哪里有近距候选、哪些区域看不清、应该先复核哪里”。希望边缘 Agent 能辨认这种能力缺口，在部署方授权的范围内开发并复用只读软件插件。

## 设计与契约

站点通过 `EDGE_READ_PLUGIN_FAMILIES` 声明可委托创作的能力族、结果含义及独占的发布命名空间。Agent 的本地模型判断完整请求是否属于能力族；已安装时按授权绑定调用，缺失时留下 `planner.plugin_gap`。独立 watcher 向本地模型请求候选名称、描述与受限程序。部署方提供受信适配器、算子、输入输出合同和独立验收数据。模型选择的分位数、覆盖守卫、阈值比较和排序规则直接影响结果。发布方验证 DSL 与保留用例，再生成 DSH v2 soft/read 描述符、内容摘要和精确 binding。宿主热加载。原任务保留缺口状态，watcher 以独立任务续办并关联原始请求。

初始能力族使用经过校验的新鲜深度观测。每列有效覆盖率低于 60% 返回未知，其余按有效光轴深度的第 10 百分位和含等号的距离阈值判定，候选从近到远排列供人工查看。测量输出描述相机视区，不证明可通行空间。改变算法族、框架、权限或执行物理动作须走独立发布或控制审查。其他只读请求仍由普通规划器处理。发布方和审阅数据服务的容器、账号入口和现有 Jetson 部署步骤见[现场部署说明](../testing/field-plugin-deployment.md)。

## 验收与证据

| 编号 | 验收与核验方式 |
| --- | --- |
| AC-1 | 首次请求记录模型选择、能力缺口、模型原始候选、独立用例、发布回执、加载前后宿主身份和首次派发。错误比较、排序、低覆盖、损坏或缺失数据必须按合同拒绝或输出未知。 |
| AC-2 | 改变视区划分和阈值后重新提交自然语言任务，核对相同工具版本与绑定、不同操作 ID 和新帧。核查作者状态目录，重复调用不应再次发起创作。 |
| AC-3 | 实机记录中保留误路由、未通过验收及缺分量的历史。读取新鲜相机帧时可以独立处理缺失里程计；依赖里程计的插件继续拒绝缺源。 |
| AC-4 | 核查 Docker 重启策略、鉴权 Console、服务端点和发布者权限。现场无需底盘命令。宿主断电重启须另行安排演练。 |

首次创作由 Jetson 本地模型产出受限程序，完成独立验证并热加载。两区复用任务使用相同 `field.depth_column_review` 1.0.0 与绑定（前缀 `acdd5b4a`），在新帧得到左区 0.923 米、右区 0.378 米。以 0.85 米筛查时仅右区进入人工复核，期间仅有一个创作作业。普通规划器在早期试验把包含覆盖率与排序的请求退化成最大值和极差；该次结果不能作为筛查成功的证据。修正后仍需逐次核对原任务与输出，各类口语表达的路由准确率尚未量化。

## 迁移与回退

站点显式启用创作范围、独立发布者与审阅服务。回退时先停发新创作，再按 DSH 正规流程撤销新绑定并排空在途读取。保留任务账本、作者回执、匹配的注册表及制品，以便追溯已有任务。卸载本次可选配置可恢复旧站点的普通规划与原有逐源要求。
