# SDD-003 · 单机器人系统与故障回归

## 背景与价值

现场错误可能跨越模型、工具、ROS 与观测台。即使任务显示成功，也可能引用错误的动作或过期的观测。开发者需要用公开入口、独立世界位姿、执行账本和历史回放交叉验证。历史样例描述指定运行，不能代替候选版本的验收。

## 设计与契约

在每次独立 Docker 仿真记录代码版本、镜像身份、运行编号、注入条件、结果与日志。同一条命令适用于本地和 CI。实验使用独立容器、测试数据卷和回环端口；真实模型额外使用显式选择的本机模型缓存。测试运行目录和提交到 Git 的文档、精选证据分开保存。

## 验收与证据

- AC-1 从自然语言、模型、工具到控制器验证成功路径、幂等与失败边界。既有操作和新目标冲突时不得报告成功或重发运动。
- AC-2 覆盖室内外导航、受限区域、实物遮挡、取消、重启、链路故障及传感器异常。运动结论注明采样来源、误差、停稳条件。
- AC-3 验证观测过期、时间与坐标异常、归档中断、事件重复和回放。任务终态、故障码、因果关系及场景记录与实际证据一致。
- AC-4 一键复测提供机器可读结果、逐阶段日志和复测命令。CI 使用同一套验收。区分故障注入、真实模型与物理硬件测试，明确跳过或失败的阶段。
- AC-5 从干净检出通过项目文档索引打开规格、报告与引用的精选证据。发布材料在 `docs/evidence/`，独立验收的原始记录按 AC-6 归档。迁移保留已发布文件的 Git blob、版本与运行编号。
- AC-6 每个独立验收运行号只对应 `artifacts/verification/<运行号>/`。合并前核对全部同名文件的字节与相对路径；合并后已有运行数据全量校验通过，精选文件能够随干净检出打开。新日志和未精选 JSON 默认由 Git 忽略。

AC-1 至 AC-4 的本地验收使用 `c113b9b`，18 个阶段全部通过。实测页包含旧版反例、独立世界位姿、板端软件暴露的资源边界和黑盒、白盒复测入口。[验收结果与复测方法](../testing/sdd-003-results.md)

## 迁移与回退

保留原数据卷、历史证据和 ROS 接口。遇到跨版本回执无法证明的在途动作，保持可查询状态并标明原因。回退到原镜像前结束或核实在途运动；本地系统测试只清理该次临时环境。
