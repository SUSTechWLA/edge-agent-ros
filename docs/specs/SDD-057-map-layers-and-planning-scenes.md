# SDD-057 可插拔地图表达与机器人规划场景

阶段一已实现本地归档地图提供者、场景查询服务、真实进程的在线装卸及只读回放工作台。基线为 2026-11-23 的 SDD-056 轮式车工作树，设计参考并行的 SDD-051、SDD-055 导航与感知实现。多视角配准、跨机型精细规划和 Jetson 实时负载验收仍待实施。

## 背景与价值

车绕箱体，需要知道车身扫过的位置是否被占用、多少空间已观测。机械臂抓取带标识的零件，还需要从外观确定目标，从深度估计表面与位姿，并检查所有连杆和手中工件经过的空间。同一批观测可产生不同地图，两项任务也可以在同一环境使用不同分辨率。

| 已有实现 | 可复用的行为与边界 |
|---|---|
| [双 MID-360 近场](../../perception/rover_plan_field/scene.py)、[D435 纹理三角面](../../perception/rover_plan_field/rgb_scene.py) | 雷达输出车体坐标下的 10 cm 占用单元。D435 用对齐深度、内参和 RGB 重建光学坐标中的单帧表面，深度断层处保留空洞。已有 Jetson 归档的两个场景时差约 20 分 17 秒，场景间相对位姿为空。它们可作为拒绝错误配准的现成反例。 |
| [累计栅格](../../task_recorder/global_map.py)、[点云地图与查看器](../../perception/map3d/README.md) | 已有栅格身份、重置分段、修订、摘要与回放。点云可按采样时刻做 TF 变换。校园纹理包具有仿真来源。三类数据均可保留原格式。 |
| [轮式单帧规划](../../perception/rover_preview/README.md)、并行分支的导航与感知能力索引 | 当前 `planning.local_path` 1.1.0 消费车体射线和回波。SDD-051 的地图及路线以严格 v1 结构计算摘要。SDD-055 的只读索引已在 Tool 间选实现，空间事实可引用独立制品，也有依赖站点外参和静止见证的单窗融合。这些能力分属工作树，合并与联合验收另计。 |

Tesla 在美国当地 11 月 21 日宣布 FSD v15 开始推送。按其公开技术说明，最近一段车载视频的视觉编码特征被驾驶与显示分支复用。Reality View 的独立生成分支结合前一段画面生成虚拟俯视视频。公开说明对屏幕如何生成给出了依据；驾驶内部是否保存可跨任务复用的米制纹理网格、其尺寸精度如何，仍缺公开证据。本设计借鉴观测复用，并为可执行规划所需的几何建立独立质量证据。[Tesla 发布公告](https://x.com/Tesla/status/2124222447855743019) · [Reality View 技术说明](https://x.com/elonmusk/status/2124458557525397780)

## 设计与契约

### 提供者怎么分工

| DSH 扩展点 | 状态所有者、输入与输出 | 消费者 |
|---|---|---|
| 观测与定位 | 复用现有 ROS 只读桥或录包读者。分别发布 RGB、深度、点云、相机内参、带时间的 TF、机器人关节状态及来源。定位提供者负责自身代次和质量。 | 建图、识别、独立验收、查看器均可消费。 |
| 地图表达 | 每个软件提供者拥有自己的融合状态、分块与检查点。几何可输出二维占用、彩色表面、距离场；外观可输出实拍纹理或生成视图；物体提供者输出实例、位姿假设、误差与遮挡；动态跟踪单独发布带有效期的轨迹。 | 使用者按所需量查询已发布图层。识别可使用纹理；净距查询须取得满足其质量要求的几何。 |
| 场景快照 | 由站点指定的只读组合服务核对坐标、采集时间、定位代次和覆盖，固定一组相容的图层修订，发布不可变清单。所有者原子发布清单，只引用已完整写入并核验的制品。 | 同一次规划、复算、前端回放可按相同摘要读取。纹理单独更新时，纯几何规划的输入摘要保持一致。 |
| 规划与复核 | 提供者声明支持的目标、机型、候选类型，以及实际需要的原始观测、历史、位姿或地图图层。按声明读取输入，返回候选及其依据，或说明缺失条件。独立复核可重算净距、碰撞或目标是否可见。 | Agent 按任务要求和现有证据选择能力。高频请求可由常驻消费者调用，调用方保留适用时限。 |
| 可视化与物理执行 | 查看器将实测表面、待观测区域、推断外观、带时刻的轨迹作为独立图层，可逐层关闭。候选路线仅有读取效果。运动授权、执行前的新鲜度复核、设备独占与停稳见证归相应物理 Runtime。 | 技术人员可区分“表面被看到”“此处可以通过”“已实际到达”。首轮只读回放。 |

DSH 的 Definition 描述消费者所需的**结果及保证**。例如“工作台区域中，以米计的障碍距离、误差界和已观测掩码”。具体实现各自使用唯一导出名，站点 pack/profile 的能力索引将等价实现归到同一 Definition。内置算法、用户 workflow、ROS 适配器或 Agent 验收后发布的实现都可参与。扩展已有索引对 Service 的筛选，复用已有注册、健康、排空和版本绑定。当前 [Service 目录](../../edge_contracts/service_directory.py) 要求导出唯一；新增算法用独立导出，通过索引选择。现有轮式端点继续原样服务旧调用方。

### 如何表达地图，怎样按用途读取

- **地图身份与图层引用。** 新版清单在旧 `map_ref` 外部引用其原始摘要。局部工作台也可以只锚定可信的机械臂基座帧。每层记录 schema 和语义版本、用途、内容摘要、生产者 binding、源码或镜像身份、源观测引用、覆盖域、坐标轴/单位、时钟与采集时间范围、标定/变换链以及适用时限。定位跨代、跨楼层或跨机器人时，只有具名且已核验的配准才能连接两个空间。
- **显式区分实测、推断与未知。** 表面命中、射线穿过的自由空间、视野外或遮挡空间分别编码。语义或补全模型可提议目标和下一观察位置。精确操作要求每个关键表面能追溯到度量证据；颜色采样密度、体素边长和物体检测分数各有其单位，不能替代位姿误差。运动物体带时间窗和预测不确定度，从静态背景隔离；过期后恢复未知，待新观测澄清。
- **区域与分辨率。** 工作区的粗地图适合底盘，手边的小范围可维护更细的 TSDF（用于融合带尺度的表面）、彩色网格或 ESDF（用于最近障碍距离查询）。调用方声明区域、所需量、最大误差、允许年龄/时差、未知处理和计算预算。返回精确修订、坐标、采样间距、质量和覆盖。超出地图边界、分辨率或误差预算时报告原因及缺少的观测。
- **读写与更新。** 发布者是各自数据的唯一写入方，普通消费者只读。计划记录其实际依赖的图层修订、机器人与工具模型、起始状态及算法绑定。长任务保留算法绑定，每次重规划可以读新鲜场景并产生新计划修订。只改显示颜色时，旧几何仍可复算；若任务依据标签认物，外观与物体位姿同样进入该任务依赖。地图换代、手眼标定变化或目标被移动时重验受影响的计划。
- **高频数据面。** 图层引用和查询参数通过 Service 传递。点云、网格、图像等大块数据按内容寻址或经有期限的本地只读缓存访问。按区域、分辨率和期限限制读取；增量必须指明基础修订，缺块时重新读取完整快照。每类消费者有独立 CPU/GPU、内存和队列预算，慢纹理渲染可丢帧。局部避障沿用已有 50 ms 软计算预算，端到端年龄和 Jetson 实测分开验收。

首版拟提供以下三个独立的读操作。名称用于说明接口，发布时由各提供者的清单声明唯一导出。

| 操作 | 输入与返回 |
|---|---|
| 固定场景快照 | 输入主体、任务坐标系、感兴趣区域、所需图层及各自的时效/误差要求。返回不可变 `scene_ref` 和满足要求的图层引用；有必选项缺失时返回具体缺项及可供人查看的独立观测。 |
| 查询指定图层 | 输入 `scene_ref`、图层引用及区域、查询点或分块键。距离查询返回米制距离、已观测掩码和误差；表面查询返回几何、纹理及其标定来源。未来的 3D Gaussian Splatting 或 NeRF 提供者可以先实现视角渲染。要再提供米制查询，需要单独通过该项验收。 |
| 试算规划 | 提交目标、机型、所需候选类型与约束，按所选能力提供起始状态和证据。消费地图的实现可要求 `scene_ref`；消费传感器的实现可以直接绑定观测。返回实际使用的数据和提供者版本，以及指定类型的候选或拒绝原因。沿用各实现已有的路径或轨迹 schema。 |

### 导航如何同时支持地图、视觉语言与端到端策略

“经过门口，到有蓝色标牌的办公室附近”可以直接保留语言指令；若用户指定楼层和地图坐标，则还要保留其坐标系与验收容差。是否需要全局地图、持久定位、度量深度或语言模型，由各实现声明。站点只在目标含义、机型约束、输出语义和质量要求都相容时选择备用。自然语言目标不能在缺少独立地点关联的情况下被替换成任意坐标；也不能用局部“观察到标牌”直接验收“全车到达”。

SDD-051 的 `nav_plan` 属于地图路线契约，保留定位代次、地图引用和路线摘要的原校验。只给出观察方向、局部路点或短时动作候选的实现使用各自的只读 Tool 与结果契约，经站点能力索引登记。任务要求全局米制路线时，只读语义建议不足以满足该请求。接入新策略无需向 v1 路线填入虚构的地图引用，也无需给建图服务增加对导航模型的依赖。

| 可选实现 | 它可以绑定的输入 | 输出与可验证的含义 |
|---|---|---|
| SLAM 定位与地图路线 | 带版本的地图、定位、坐标目标和车体模型 | 带地图帧与修订的路线；定位失效时列出缺失的位姿依据。 |
| 视觉语言导航（VLN） | 语言指令、同步或有序的图像观测、模型声明需要的历史和机器人状态。部分策略也可消费局部地图 | 给下一步提出有时限的局部航点、观察建议或停止建议。图像中的方向只有经过标定和度量验证后才能转换为米制航点。 |
| 端到端策略 | 按模型训练和标定时的定义绑定传感器窗口、机型状态、目标、预处理与模型版本 | 声明具体的候选表示，例如车体局部轨迹。输出动作序列的模型须由适配器解释动作空间、步长、单位、时域和机型边界；无兼容解释或观察不足时拒绝该候选。 |

规划软件只读。机体局部候选记录参考帧、观测时间、单位、适用时限及依赖；基于地图的候选另记真实地图引用。时序模型需核对其所需观测的新鲜度、时钟和前后顺序。提供者换版或掉线后，若模型历史无法按绑定恢复，向新提供者重放可用观测或请求重新采样。模型提出停止时，前端显示“建议停止”；到达、实际停稳、制动和设备操作分别由已有任务验收方和物理 Runtime 见证。闭环导航验收还须以独立真值记录成功率、最小净距、误停、延迟与超期拒绝。SLAM 定位评测与语言目标完成率各按自身适用范围报告。[轮式只读规划与物理边界](SDD-056-rover-local-plan.md) · [物理执行交接](../architecture/plugin-physical-handoff.md)

例如“把带蓝色标识的零件放进夹具”。识别提供者可从纹理得到零件候选；位姿提供者结合多视角深度、模型和关键点给出带误差的 6D 位姿。规划提供者绑定关节初态、机器人模型、工具中心点（TCP）、夹具几何和接触规则，检查抓取前、夹持后和放置时所有连杆、夹爪及工件的扫掠空间。若零件对称，保留多解并判断这些解是否影响抓取。若目标被遮挡或误差超过装配公差，返回需要补拍的区域，保留其他只读任务的可用性。

| 规划种类 | 所需输入 | 候选输出 |
|---|---|---|
| 轮式车静态绕行、探索中的局部绕行 | 车体观测、外廓、局部目标和观测覆盖。探索插件自行选择前沿 | 沿用现有二维曲线路径，绑定车体帧和采样时刻。原始快照可直接送入 1.1.0；地图适配器若要生成射线，须保存实际自由空间的证据。 |
| 无人机或动态避障 | 三维占用/距离、机型动力学、三维约束；动态策略额外消费带时间和不确定度的预测 | 有时间参数的三维或地面轨迹及有效期。静态规划器只声明静态能力。 |
| 机械臂预抓取、放置 | 标定到基座的工作区几何、目标实例和位姿、关节状态、关节限制、夹具、工具和载荷 | 按具名关节和单位给出时间轨迹、起始状态、工具版本、最小净距及不可行原因。候选中约定接触哪些表面，实际接触和抓稳需另外见证。 |

第一候选后端可用 CPU 彩色深度融合做可复算基线，再评估 Jetson 上的 nvblox。机械臂可将快照适配为 MoveIt Planning Scene，在独立场景中运行只读试算。两者都是可替换的实现选择。要恢复精确操作，固定相机需要相机到机械臂基座的实测外参，腕部相机需要手眼标定和采集时刻的关节运动学；还须验证工具中心点、深度尺度和时间同步。根据实际任务公差分配平移、角度、深度、配准、位姿及跟踪误差。用独立量具或标定靶量测覆盖与误差，记录可用距离、视角和材质。[NVIDIA nvblox 表达与图层](https://nvidia-isaac-ros.github.io/v/release-4.0/concepts/scene_reconstruction/nvblox/technical_details.html) · [MoveIt Planning Scene Monitor](https://moveit.picknik.ai/humble/doc/concepts/planning_scene_monitor.html)

## 验收与证据

以下是拟实现后的验收门槛。输入阈值由任务、机型和标定记录预先给定。

| 编号 | 输入或故障 | 独立可观察的判据 |
|---|---|---|
| AC-1 兼容与卸载 | 重放相同的轮式 clear、centered、近障输入，禁用纹理，再停用优先地图提供者 | 前后比较旧接口的路径、覆盖与保持原位结果。关纹理允许几何继续；新请求仅选择满足相同精度与证据要求的备用提供者，旧收据仍可读，历史摘要一致。 |
| AC-2 防止错误配准 | 回放当前归档的异时 RGB-D 和雷达，注入同名帧异站点、错手眼标定、过期动态层 | 能分别查看原观测；融合请求返回缺失的变换、时间、代次或质量原因。隐藏区域的占用状态维持未知。 |
| AC-2a 单曝光 RGB 纹理 | 使用一组对齐的深度、原始彩色 PNG 与相机内参，从同一视角切换几何和纹理，并导出可离线打开的地图 | 表面像素能按 UV 回到原图，深度断层和孔洞不生成面。导出的三角形、米制尺度与嵌入图像能独立复核。停用纹理提供者后拒绝新导出。雷达跨帧配准另行准入。 |
| AC-2b 跨传感器着色 | 在隔离 Gazebo 中采集两个独立的三维激光和 RGB-D。把采集、标定和时间证据固定后，对两路点分别投影，并对照世界几何和色块。用错外参、错时钟或错时刻作反例。 | 独立验证两路三维点、颜色和覆盖；报告分母与各类拒绝数。相机看不见的激光点保留几何且颜色未知。地图和 PLY 可以由同一冻结图层读取，原实车归档继续独立查询。 |
| AC-3 机械臂工作区 | 采集同一标定工件的多视角数据，保留独立测量的检查点，覆盖反光、遮挡及对称姿态 | 分别报告平移误差、旋转误差、有效覆盖及失败样本。在预先声明的任务公差内才输出可复核候选。用独立碰撞几何检查全部连杆、夹具与持物，自碰撞或证据不足时不给可执行结论。 |
| AC-4 换版、失效与恢复 | 插件排空、崩溃、缓存淘汰、旧增量重复、目标移动、定位重置、场景清单写入中断 | 读者只见完整修订。旧计算凭原快照复算或明确说明已过保留期。新计划引用新修订。运动操作号与物理所有权不因软件换版而变化。 |

## 迁移与回退

1. **先包现有数据。** 在旁路适配旧车体快照、相机纹理面和二维地图，形成首份场景清单；查询能力、图层开关和拒绝误配先在已有回放上验证。保留旧 Tool、`planning.local_path` 与 v1 地图摘要。
2. **再补实测度量。** 建立固定工作台的同步多视角采集、外参和独立尺寸基准。首个软件后端产出带观测掩码和质量记录的局部表面、距离场；沿用同一批原始输入对比第二种后端，再验证结果等价、故障切换与资源竞争。
3. **最后接精细规划。** 引入工具模型、关节状态和物体位姿，通过仿真中的只读 MoveIt 适配器计算、复核轨迹。动态预测和其他构型逐项按各自契约接入。实际运动另经物理 Runtime 和实机验收。

新实现安装后先通过健康与质量验证，再进入站点候选；卸载前停止接新请求并排空。换版切换优先级只影响新绑定，历史计划保存原算法、依赖和内容摘要。持久融合状态通过有版本的检查点和原始观测恢复，迁移失败保留原版本，内容垃圾回收避开仍被任务或回放持有的制品。停用新提供者即可恢复原轮式接口。DSH v2 软插件生命周期与当前 v1 机器服务各沿用自身安装路径，联调通过前不宣称二者透明热换。[DSH 服务与排空](../../edge_contracts/service_directory.py) · [物理交接协议](../architecture/plugin-physical-handoff.md)
