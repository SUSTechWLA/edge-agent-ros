# SDD-041 单独交付可追溯的机器人部署分支

## 背景与价值

工厂和现场需要 Docker 镜像、驱动接入配置和启动入口。研发仓库同时维护教材、Gazebo 场景、测试与实验原件。手选文件上板容易漏依赖，手工在两个分支维护相同代码又会产生版本分歧。

## 设计与契约

维护者从已提交的源码快照生成 `deploy/robot`。保留硬件镜像的原有相对路径，按允许目录和文件选择，附一页板端说明和 `ROBOT_SOURCE` 源码指针。该分支有自己的 Git 历史，由生成器单向更新。每次更新均检查上次发布的文件树及分支占用，使用 Git 引用的比较并更新防止并发覆盖。新增设备插件在研发分支完成 SDD 和测试，再纳入发布。配置与现场观测保存在板端独立目录和 Docker 卷。

## 验收与证据

- AC-1 独立检出的部署分支可以解析硬件 Compose、构建镜像并进入只读观测。分支不含实验产物、教材、Gazebo 场景或测试源码。
- AC-2 生成器不会发布工作区未提交文件。重复发布相同运行代码或仅更新研发文档时保留原部署提交。任何人工改动的部署分支必须显式解决。
- AC-3 运行镜像可沿 OCI 标签和源码指针追溯。可用单分支 Git bundle 在离线工厂交接，既有任务数据库留在 Docker 卷中。

## 迁移与回退

研发工作树维持原目录。在设备空闲并确认停稳时切换到先前发布提交和对应镜像。生产数据由现场运维保管，分支切换不自动迁移数据库或撤销已执行的动作。
