# SDD-008 可独立部署的插件管理器与自主能力恢复

## 背景与价值

用户想让机器人扩展新能力时，现有作者能生成只读工具候选，发布器能安装受管工具，独立服务插件仍由部署者手写描述符。即使机器人已有可核对的发布契约，候选也一直等待人来复制文件。把插件管理做成独立模块，可以给 Agent 一条从能力缺口到可验证结果的自主恢复路径，也使新增工具与新增服务插件共用运维入口。

## 设计与契约

1. `plugin-manager` 作为可选 Docker Compose profile/独立 CLI。职责是受管注册、校验、发布和撤回，执行端保持注册目录只读。两种类型明确区分：声明式 `derived` Tool 向 LLM 提供调用能力；`runtime` 服务描述符引用部署方已启动的提供者，提供/依赖服务，不必向 LLM 暴露 Tool。管理器可在无模型、无 ROS 网络的环境使用。工具类型复用既有发布器、回退和验收契约。服务类型检查描述符、依赖与冲突，变更时对照预期旧内容摘要，保留请求、拒绝、结果或中断后对账。
2. 新增独立的自主处理方式。从可验证来源的作者提案触发，核对私有收据 SHA、候选版本、任务终态和来源。部署者可配置“该类意图允许自动安装的确切只读语义和独立测试样本”。候选通过后可自动发布并为原用户发起可追溯的后续任务。校验实际结果与版本，发出成功、需复核或等待依赖事件。固定任务身份、每项变更的幂等和恢复对账避免重复发布及重复下发。越权、缺契约、无法验证、原任务状态变化或版本冲突，均应给出可操作的原因。人在运行期间可停掉管理模块。
3. 政策来自只读挂载；候选不能通过提供自己的期望值扩大权限。未授权的设备运动、自动启动任意镜像、自动执行新代码仍由各自部署和设备所有者接管。首批自主恢复支持被现场契约授权的里程计只读能力，对未覆盖能力保留提案和人工入口。

## 验收与证据

| 编号 | 场景 | 可观察的成功条件 |
|---|---|---|
| AC-1 | 同一管理入口安装、升级和撤回两种扩展 | 有独立版本、来源和事件；不改设备执行内核；服务确实出现在 Agent 的目录，对应工具绑定可查询。 |
| AC-2 | 无效清单、依赖缺失/冲突、过期版本、进程中断 | 其他能力继续可用，具有变更前后的可核对记录，意图未结时对账，不误报成功；重复请求不能覆盖别人的新版本。 |
| AC-3 | 用户提出已授权的只读需求，原任务因缺能力失败 | 作者提出候选后，管理模块自行采用独立样本、发布、发起关联的后续任务。后续任务读取真实 ROS 消息，得到相应的变换值。 |
| AC-4 | 重启、重复提案、候选伪造、契约不匹配或传感器失联 | 不重复派发；不能用不同工具/版本的回执声称成功；需介入时输出原因与建议操作，外部状态不确定时可以复查。 |
| AC-5 | 卸载管理器、旧命令、不同部署形态 | 既有 Agent、工具和已安装插件仍可运行。隔离容器、ROS/Gazebo 回归，记录当前硬件验证范围。 |

## 迁移与回退

新能力通过 Compose profile 安装，保留旧发布 CLI、Agent API 和历史事件。部署者显式选择自动化契约；有效契约允许相应任务无需逐次批准。在停止管理进程后，已保存的任务、事件和已安装能力继续可查。回退某次安装要核对当前版本再操作。
