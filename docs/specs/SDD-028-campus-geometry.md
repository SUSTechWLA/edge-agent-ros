# SDD-028 校园三维场景的几何与可验证性

## 背景与价值

开发者在 8773 的三维透视中看不到校园楼群，教学楼与田径场也很难辨认。原来的正射纹理加最高点高度图适合俯视。一个平面坐标只存一个高度，无法表达同一坐标下的屋檐、墙面和地面。Gazebo 场景里的教学区与体育设施本身也需要检查。目标是让开发者从校园总览进入地面视角，并能核实所见几何来自哪一份仿真场景。

## 设计与契约

场景插件负责离线资产、米制摆放、碰撞和相机。地图插件读取同一世界版本的几何与来源，发布带 SHA-256 的本地 GLB。浏览器按书签提供的相机位置查看楼群、教学楼和运动场。ROS 位姿、实测点云和栅格继续通过原有接口叠加。

## 验收与证据

| 编号 | 可观察结果 | 验证方式 |
|---|---|---|
| AC-1 | 校园包含一组有地理出处的真实建筑。记录来源、授权、坐标变换、精度和仿真补建范围。 | 检查离线输入、建筑数量、空间范围与内容校验。 |
| AC-2 | 同一份场景定义驱动 Gazebo 和三维页面。俯视可见楼群，斜视能看到垂直墙面、屋面及设施之间的空地。 | 检查导出的三角面、材质、坐标和场景身份，浏览器截图验证。 |
| AC-3 | 教学楼入口在仿真中保持可通行。足球场在跑道内，从地图能辨认直道、弯道、球场界线与球门。 | 检查入口净空、场地尺寸及各设施位置，分别查看街面和场地视角。 |
| AC-4 | 默认三维视图可用，一步可到楼群、教学楼与运动场。模型加载失败时给出真实的显示状态，二维地图和已有机器人数据仍可使用。 | 洁净浏览器打开页面，测试书签、交互、回退和二维地图。 |
| AC-5 | 在独立校园 Docker 项目验证后切换本地服务，保留可复现命令、版本和实际验证边界。 | 运行插件和场景回归，核对正在服务的模型与 Gazebo 身份，留存证据。 |

## 迁移与回退

沿用 scene 与 map3d 插件边界。机器人观测点、实时位置、仿真先验保持各自含义。模型与纹理使用本地静态资源。三维资产和浏览器渲染可独立回退。采用本地投影并保留世界坐标依据，无法从地理数据获知的内饰、窗户和装修要标为仿真设计。切换运行场景前检查当前任务及运动状态。场景或模型身份不匹配时拒绝叠加。
