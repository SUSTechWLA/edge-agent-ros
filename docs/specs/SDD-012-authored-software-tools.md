# SDD-012 · 从软件任务的能力缺口起草并热装只读工具

## 背景与价值

基线 `50b9344` 的 derived Tool 可以让模型选择里程计字段、单位与阈值。纯软件工具可以通过 HTTP 由开发者另行部署，但当用户输入“计算相邻采样间隔的最大值 [100,103,111,115]”时，旧作者不能定义需要的操作。将同一受管发布流程扩展到用户提供的数据，可以在完全没有 ROS 传感器的情况下验证自主扩展。

## 设计与契约

沿用原 Definition、Tool、plugin author 和 plugin manager。新增 derived 清单 schema 2，由模型在已有算子中选择最多四步有序的数列变换和一个归约。输入为任务明确给出的有限整数 JSON 数组，1–128 个元素，每项绝对值至多 10⁹。支持相邻差、取绝对值、升序、保持首次出现顺序的去重，归约可求极值、和、均值与个数。返回计算值、原数组摘要与变换前后长度。输入数据不需要上送作者模型，检验失败或输入/输出越界时保留诊断。

作者只提出候选，独立样本定期望，受管发布者负责比较现有版本并登记结果。计划固定声明内容摘要。执行解释器只读步骤参数。已有里程计 v1 注册和恢复保持兼容。现场自动恢复以受理的原任务、来源、精确授权语义、独立样本和证据对账为边界，相关实现和验收由同一规格追踪。

### 从原始请求到一次有依据的回答

任务“计算相邻采样间隔的最大值 [100,103,111,115]”在首次运行时没有可用工具，终态为 `BLOCKED`。作者从原任务查到未派发的规划故障，仅将能力描述和输入类型传给 Ollama。候选的可复用部分如下。

```json
{"schema_version":2,"id":"derived.sample_gap","description":"计算相邻采样间隔的最大值","transforms":["diff"],"reduce":"max"}
```

发布者用三组事先写明期望的样本检查定义。例如 `[100,75,90]` 的间隔是 −25 和 15，期望最大间隔为 15。只有候选通过全部样本才写入正式目录。随后 Agent 发现新版本，按完整能力名称匹配原任务中的数组，派发 `{"series":"[100,103,111,115]"}`。执行器返回 `source=arguments.series`、输入摘要、长度 4、差分长度 3 和最大间隔 8。一次调用可以通过 operation ID 查到调度、工具请求、工具回执与步骤验收事件。安装、撤回和换版复用受管发布协议，回执包含 change ID 与发布事件 ID。

现场开发可用下列命令复现。第二条启动独立的 Agent 和 Ollama 容器，从本机缓存卷只读复制模型，在临时目录发布和撤回工具。测试显式挂载当前 Agent 源码，报告保存每个模块的 SHA-256、基础镜像 ID、模型摘要和请求/回执归属。它检验手工驱动的发布流程，自动接手流程由 AC-5 单独验证。

```sh
python tests/test_series_tools.py -v
python tests/system/series_author_acceptance.py --image edge-agent-ros:v0.1 --cache edge-agent-ros_models --out .ci-results/system/series-author.json
```

规划入口按完整已登记名称匹配数列任务，例如“最大间隔”和“最大间隔的总和”可并存。模型提出的工具和数列也要与原请求匹配。112 与 121 的顺序、负数符号都影响结果。在途观察型旧任务遇到同 ID 的新数列工具，先拒绝不匹配的版本绑定，然后由既有恢复路径处理。当前 v2 的输入、变换和归约类型均有限；需读取新设备、调用新协议、理解图像或实现新算法时，另选 HTTP Tool 或独立 Service 扩展点。

AC-5 的现场策略固定用户原文、允许的变换及归约，并预先给出包含原请求输入的独立期望样本。发布者检查样本，管理器保存本次下发的原文和期望。原生步骤必须回显同一组参数、内容版本、数列摘要及独立期望值才能确认恢复。进程重启读取原下发快照。验收时原请求保持 BLOCKED，新的只读任务携带同一 trace 和发布事件，重复投递只认领一次。

AC-5 的完整模型实验保存在本机运行 `20261118T021512Z-e6284bdf/plugin-manager-model.json` 的 `stages.autonomous_software_recovery` 中。实验只提交了一次用户请求，原生任务受阻后，作者、策略审批、发布、续办、独立结果核对均通过；在没有里程计服务时算出 8。相同 trace 能同时查到原失败与新的成功记录。复现入口为 `tests/system/plugin_manager_acceptance.py --image <候选镜像> --ollama-cache-volume <模型卷> --out <结果文件>`。

## 迁移与回退

### 来自已验证回执的纯计算

另设版本化表达式语言 `numeric.rpn.v1`，支持对一个有序有限实数列取统计量，再以标量四则运算组合结果。作者只能提交 JSON 记号数组。输入由调用方从已验证的观测回执提供，解释器只接收数值。表达式版本由语言版本和规范化记号共同确定，回执同时固定输入的摘要。

AC-6 要求独立于候选的期望样本覆盖不同输入与不同输出。解释器对同一程序和数列给出相同回执。错误栈、缺测、非有限数、越界、未知记号、除零或样本不符时拒绝执行或验证。样本通过仅说明候选符合这些案例。验证器不授予发布权限，发布和撤回归调用方的受管站点负责。已有 v1 和 v2 定义继续按原协议读取。

使用相同 derived 目录和受管发布器；准备包含 schema 2 解释器的 Agent、作者和管理器，再发布新清单。卸载使用当前定义的 SHA，恢复旧清单仍需原独立样本。回退运行镜像前排空在途 v2 步骤并撤回 v2 定义。旧软件可继续读取历史任务，旧运行时无法调度 v2。旧操作遇到换版按现有绑定恢复规则处理。
