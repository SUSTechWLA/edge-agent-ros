# Edge Agent ROS v0.1 产品需求与架构

本页保存首轮巡检内核的开工基线。后续已落地的自然语言代理、插件、传感器观测、回放和平台验证，见[当前版本使用手册](../console.md)与[部署矩阵](../deployment.md)。

## 要交付的产品

开发者在一台有 Docker 的电脑上启动单台模拟轮式机器人，提交“依次到 A、B 两个观测点巡检并记录到达位置”。Edge 自主将委托展开为导航、停稳、采样和验收步骤。开发者可查询进度、取消委托、重启内核，取得与真实 Gazebo 物理运动相符的证据。该版本冻结于实现之前；运行结果另存验收报告。

| 角色 | 用户可做的事 | 产品承诺 |
|---|---|---|
| 上层 Brain 或开发者 | 用唯一任务 ID、平面观测点列表下达委托，重试提交，查询、取消 | 同 ID 同内容复用状态，同 ID 不同内容拒绝；一个底盘一次只接一份活动委托 |
| Edge Agent | 保存委托，根据步骤状态选择下一动作，收集到达证据 | 网关动作成功后，还要以新鲜的里程计观测验证目标位置；第二点依赖第一点验收 |
| 机器人集成者 | 替换 ROS Action 网关、传感器或策略 | 上层委托不依赖轮子数量。首版有一个确定性巡检策略和一个差速运动网关 |
| 系统验收者 | 从 Docker 观察 Gazebo 中的模型轨迹，核对任务数据库和返回结果 | 以独立 Gazebo 模型位姿检验两个目标，不把命令已发布或返回成功当作物理验收 |

## 组件与所有权

```text
Brain 客户 / ROS CLI ── submit / get / cancel ──► edge_core (C++20)
                                                  │  单写者 SQLite 持久卷
                  新鲜 /odom ────────────────────►│  每个子目标独立验收
                                                  ├─ NavigateTo Action + 操作心跳
                                                  ▼
                                           edge_gateway (C++20)
                                             ▲ /odom    │ /cmd_vel
                                             └──── ros_gz_bridge ─────► Gazebo DiffDrive
                                                                         │ 物理模型位姿
                                              独立验收客户端 ◄─────────────┘
```

ROS 2 Jazzy、Gazebo Sim Harmonic、Docker Compose。宿主不需要原生 ROS 或 WSL 开发环境。采用一个应用镜像、按职责分服务，项目自己的 Docker 网络和命名卷隔离仿真。第一版评估空旷且已知的平面巡检；后续有障碍物的地图可替换为 Nav2 网关。首版结构化委托是 Brain 接入口；云端 Brain、自然语言模型、跨机协调、ARM64 真机及可装载第三方插件属于后续版本。此版本不需要模型密钥。

## 验收标准

| 编号 | 验收标准 |
|---|---|
| A1 | Docker 内构建 C++ ROS 包，从自带 SDF 启动 Gazebo 和 ROS 桥，不依赖在线模型或素材 |
| A2 | 默认巡检 A(0.8, 0.0)、B(0.8, 0.7) 米。两点依次有观测证据，里程计误差各 ≤0.12 m，Gazebo 模型真值误差各 ≤0.18 m；原点明显移动，两段转向与运动实际发生 |
| A3 | 对重复、冲突、空点、越界和并发提交有明确结果。取消活动任务后底盘停止，已完成的任务可查询 |
| A4 | 正常重启仍能查询已完成任务。执行中丢失内核或运动反馈时停止继续驱动；无法证明结果的遗留动作进入恢复待核查状态，禁止自动重发 |
| A5 | 提供一条部署命令、一条可重复验收命令、环境版本、机器可读轨迹证据和已知范围；测试失败以非零退出，支持新 Docker 项目独立复测 |

## 开工顺序与模块说明

1. 冻结[ROS 接口](interfaces.md)、[任务内核](core.md)、[执行网关](gateway.md)、[仿真与交付](simulation.md)。
2. 实现接口包、内核、网关、仿真 world 与桥。
3. 在 Docker 运行真实任务及故障用例。把观察到的符合项、失败及修正后的实测结果写入验收记录。
