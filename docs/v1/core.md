# 模块二 · 本地任务内核

输入是持久 ID 和有序观测点。输出是可查询的进度、每个已验证点的实测位置和终态详情。核心包 `edge_core` 使用 C++20、rclcpp 和 SQLite；SQLite 数据目录挂 Docker 命名卷。ROS 回调串行修改任务状态。

1. 提交时检查身份键、数值、活动占用。已见 ID 比较全部点，对相同内容返回原状态，无需重走。先写任务及目标，再返回接受。
2. 确定性策略从第一个尚未验收的观测点选择 `navigate_to`，建立稳定操作 ID 并写入动作意图后发送 ROS Action。同一任务最多一个在途动作。向网关刷新该操作的活动心跳。
3. 网关完成后，单独取到达回执之后的本机里程计观测，检查与目标的距离 ≤0.12 m。保存任务、步骤和实测证据；全部通过才进入 SUCCEEDED。等待网关、运动和等证据均须有时限。
4. 收到取消时阻止后续步骤，通知网关；区分受理取消、确认停止与动作结果未知。失败需返回阶段/原因，重复或迟到的回调不能覆盖终态。
5. 启动时恢复历史，非终态任务保守转 RECOVERY_REQUIRED，不自动重发。结果未知时保留底盘占用，验收在隔离项目内进行。运营恢复必须先单独核实机体与旧执行器的安全状态；这一版以停止仿真并使用新实例作为受控复位边界。

诊断定位顺序为任务 ID → 步骤/操作 ID → 导航结果 → 独立位置观测。未来模型只能提出候选动作；首版策略不调用外部 API。

现版的 [PolicyPort](../../src/edge_core/include/edge_core/policy.hpp) 与 ROS 解耦。策略读取只读目标和已验收步数，返回前往某步、完成或受阻的提案。内核独立验证所提步骤、目标及是否真正全部验收。更换策略实现不需要更改底盘网关，首版策略在构建时注入。

## 查一条实际任务

`missions` 保存当前状态与原因，`steps` 保留每个点的目标、稳定操作 ID、网关结果、验收坐标和源时间戳。动作 ID 为 `<mission_id>/waypoint/<从1开始的序号>`；数据库中的 step 列从 0 开始。`submit`、派发、验收各自写入事务；SQLite 的单写者锁和底盘唯一索引分别防止双内核和双占用。[账本实现](../../src/edge_core/src/ledger.cpp) · [持久化测试](../../src/edge_core/test/ledger_test.cpp)

默认实例运行时，执行 `docker compose exec -T core /usr/bin/python3 /opt/edge/tests/export_ledger.py`，可在一个只读事务中取得完整性检查、任务和步骤快照。终态原因与步骤证据可定位此版闭环；逐事件审计、模型调用追踪和远程身份管理属于后续扩展。
