# 灵遨轮式车的双雷达、相机与 IMU 标定

目标是让前后两台 Livox MID‑360 的测距点，在 D435 真正看到同一表面时取得正确的 RGB，并能追溯本次使用的标定。现有实车归档的两项雷达安装变换来自名义 URDF，现场 TF 核查缺少车体到相机光学帧的链路。相机角度已调整，应重新丈量并留存当前装配。此流程用于工位人员与离线回放，运动权限由现场独立管理。[实车归档](../../artifacts/verification/jetson-field-scene-20261123/sensor-evidence/manifest.json) · [工厂插件](../../calibration/README.md)

## 从装配到发布

1. **冻结设备与模式。** 记录机器人编号、两台雷达与相机的序列号、各 IMU 的真实来源、安装日期、分辨率与帧率。以同一个机械基准建立车体坐标，量出安装位置和朝向作初值。对照实际 TF 树区分 `base_link`、`base_foot`、相机机壳与 `camera_color_optical_frame`。固定 D435 支架后给该次装配编号。明确哪一台 IMU 给主里程计提供数据。
2. **留一份能重算的原始包。** 用 `ros2 topic list -t` 和 `ros2 topic info -v <话题>` 核对站点名称、类型和 QoS。用 `ros2 bag record -o <新目录> <实际话题…>` 同时录前后雷达原始点及各点时刻、主 IMU、彩色、对齐深度、CameraInfo、`/tf` 和 `/tf_static`。记录曝光和设备时钟域、PTP 锁定状态、主机接收时间及时间换算方法；用 `ros2 bag info` 查计数，再解出 header 和逐点采样时间查缺帧、跳时和跨度。Livox 自定义消息保留 `timebase + offset_time`；已抽样的预览 JSON 只有接收时间时，不能据此补出扫描内时序。[MID‑360 同步规格](https://www.livoxtech.com/mid-360/specs) · [Livox 驱动与消息](https://github.com/Livox-SDK/livox_ros_driver2)
3. **先验 D435 自身。** 按当前串号和视频模式读取 K、畸变模型、深度单位和深度到彩色的注册关系。用已知尺寸的棋盘或 AprilGrid 在图像四角、中心、不同距离和倾角复核角点与深度平面。现有 RGB-D 读取契约使用对齐到彩色的深度和受支持的已校正图像。原始畸变图先按对应相机模型校正，避免二次去畸变。经独立测量通过的出厂参数可沿用。[RealSense 像素、内外参与投影](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)
4. **分别求两台雷达的空间外参。** 车体静止，在相机与前雷达共同视野放置有可同时观测特征的靶标。近、中、远布置不同位置并改变板面法向，覆盖视野边缘。采用 FAST-Calib 时用其专用靶板、输入当前相机内参，至少三个不同场景联合求解，再留出独立场景验证。后雷达若没有与前向相机直接共视，用已测量到同一车体基准的多面工装，或先求有重叠视野的雷达间变换；独立验其闭环。两块位置未知且互不共视的板不能建立共同基准。软件存 `T_A_B` 表示 B 中的点变换到 A，核对米、xyzw、光学轴，做一个已知前向点的符号测试。车体静止同一时刻有 `T_C_L = inverse(T_B_C) × T_B_L`。没有合适靶板时，可用多组有几何和纹理变化的场景做离线无靶标求解，保留同样的持出检验。[FAST-Calib 实采说明](https://github.com/hku-mars/FAST-Calib#3-run-on-your-own-sensor-suite) · [无靶标相机–雷达标定](https://koide3.github.io/direct_visual_lidar_calibration/)
5. **单独验时间与雷达–IMU。** MID‑360 支持 PTPv2/GPS 定时；核对每台设备实际锁定和 D435 时戳的来源，不能从同一 ROS 主机或 RTK 定位状态推导出三路同步。静止靶板能解空间变换，时间偏移要用运动段。优先在独立工装上给完整刚体多个轴向的旋转与变化的速度，避免只采水平直行和恒定转弯。做雷达–IMU 时空初始化时验证当前驱动消息、逐点时间与 IMU 类型。行驶中按每个激光点时刻去运动畸变，再用曝光时刻的车体位姿投影。缺少可核实的时钟关系或运动补偿时，保留局部几何与未着色状态。[LI-Init 的激励与估计范围](https://github.com/hku-mars/LiDAR_IMU_Init) · [Kalibr 相机–IMU 采集说明](https://github.com/ethz-asl/kalibr/wiki/Camera-IMU-calibration)
6. **持出验收并发布。** 拟合前单独留一组靶位和一段不同运动的回放。按每台雷达、图像区域、距离段分别报告角点/边缘重投影误差的中位与 P95（像素）、点到平面残差（厘米）、有效覆盖和拒绝率；检查遮挡边缘串色、重复拟合的平移/转角差异、两台雷达在共视区的对齐和时间漂移。用错外参或人为时间偏移作负例。按任务尺度预先约定门槛；低误差同时要有足够且分布合理的持出点。保存原始包摘要、内外参、时钟关系、坐标方向、工具/版本、留出报告和前一发布版本。

本仓库的 `python -m calibration.targets measurement.json` 从已配对的传感器/车体米制靶点生成外参候选；`fit` 至少 4 个点，`validation` 至少 3 个独立点。`calibration.factory verify` 登记安装档案与静止采样。当前工厂绑定模板只有一个 `lidar` 槽，前后雷达各需有证据；最终双雷达装配版本应明确绑定两套结果，避免同一状态目录里两次单雷达“通过”相互覆盖。工厂门控的厘米级安装验收与静止时间窗口还需配合上述彩色投影验收。[靶点求解器](../../calibration/targets.py) · [工位核验与状态命令](../../calibration/README.md)

## 在线自标定的使用位置

| 方式 | 可以获得什么 | 主要局限 |
|---|---|---|
| 离线有靶标、固定工装 | 可重复、可留出、可独立测量基准。适合建立初始设备版本、后雷达与车体关系 | 需要工位与采集时间，支架调整后要复测 |
| 离线无靶标 | 用实景多组点云与图像求解，免做专用板；原始包可重复计算 | 仍需共同结构、纹理和视野；初值、动态物体、对称走廊会影响解 |
| 在线估计或小量修正 | 在有激励的区段发现时间漂移、安装变化，持续输出残差和候选 | 平面运动、静止、恒速、低纹理或缺少共视会退化。位姿、时间偏移和外参可能互相补偿，训练段内的低残差并不能单独验收 |

上游 FAST-LIVO2 把相机模型、雷达–IMU 与雷达–相机外参从配置载入，并推荐 FAST-Calib；逆曝光是光度状态。FAST-LIO 的 `extrinsic_est_en` 针对雷达–IMU。需要相机/雷达/IMU 在线时空标定时，可另行评估 LIC-Fusion 2.0 等显式包含这些状态的估计器，逐项核定它对内参、时延和运动的假设。[FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2#15-our-lidar-camera-calibration-method) · [估计状态定义](https://github.com/hku-mars/FAST-LIVO2/blob/main/include/common_lib.h) · [FAST-LIO 配置](https://github.com/hku-mars/FAST_LIO/blob/main/config/marsim.yaml) · [LIC-Fusion 2.0 原论文](https://arxiv.org/abs/2008.07196)

建议部署时由独立标定插件发布已验收的只读版本，地图任务冻结该版本及来源。在线估计器先在旁路记录残差、候选变化与可观测性；有充分激励、在独立时间段改善且可重复时，按新版本审查发布。切换前后的地图分段，保留旧版本复算与回退。检测到相机支架变化或严重串色时，停用依赖该外参的着色，原激光几何与已验收的规划输入可继续单独读取。外参、底盘控制、运动许可由各自所有者管理。

**时间预算示例。** 图像中央、短时间、小角度近似下，横移与转动引起的错位约为 `f × (v横 / Z + |ω|) × |Δt|`。本机归档彩色焦距约 607 px。若工作距离 2 m、横向速度 0.5 m/s、角速度 0.5 rad/s，单是时间误差耗尽 2 px 预算就只需约 4.4 ms。实际还要给几何标定、去畸变、曝光与姿态估计留余量，并在画面边缘实测；静态回放允许的配对窗口不能直接搬到行驶状态。
