# 第一次进入校园，机器人怎样知道往哪走？

[打开有章节和坐标说明的录像](../../artifacts/verification/unknown-campus/mission-02/video/index.html) · [完整 MP4](../../artifacts/verification/unknown-campus/mission-02/video/task.mp4) · [下载原始录制与决策栅格](../../artifacts/verification/unknown-campus/mission-02/recording-export.zip)

这次只向 Agent 提交一次任务：“探索附近的陌生校园，建立初始地图，选一个已探明的安全位置停车复查，再回到出发点”。没有预填坐标。看完可以自己回答三个问题：一个目标点怎样从观测算出来，机器人怎样知道确实停住，后来的一项工作怎样使用刚刚建好的图。

## 一、自然语言和坐标各由谁负责

上次七站巡检的坐标由测试作者写进 `POINTS`，拼进用户请求。Agent 的 `points_in` 解析括号里的数值，生成导航调用。已有测绘坐标、且定位与地图同框时，这种方式适合验路线、测误差、查是否重复派发。初次进场时还缺少定位参照和可通行性证据。[上次请求的生成代码](../../tests/system/record_long_mission.py) · [Agent 的解析实现](../../agent/planning.py)

这次通过现有 Agent 工具协议注册实验能力 `survey_nearby`，使用确定性的本地规划入口匹配这句任务，无需模型 API。工具接受空参数。新建的任务空间没有地图、具名地点或路点文件；仿真服务保管原校园几何，独立观察器可以看到世界真值。任务执行器读取车载感知形成的 `odom` 位姿和占据图，提交、查询和取消已有 Core 动作。这一实验中的输入隔离用于验证算法，开放的 ROS 域还需单独做生产权限隔离。[实验接线与一次提交](../../tests/system/record_unknown_campus.py) · [工具提供者](../../tests/system/campus_survey_tool.py) · [感知节点](../../perception/node.py)

| 决策 | 实际如何得到它 | 录像里可以对照什么 |
|---|---|---|
| 出发点 | 等待连续更新的地图与融合位姿，把首次有效位置记为家 | 任务已经受理、感知尚未接入时，目标数为零 |
| 下一个探索点 | 找连通的已知自由区与附近未知格，给车体留 0.30 m 余量，按预期可发现的未知格和路线代价选前沿。沿安全路径每次只取不超过 0.65 m 的一段 | 第一幅用于决策的图上，前沿约为 `(-0.05,-1.75)` m；实际只提交 `(-0.05,-0.55)` m |
| 故障恢复后的点 | 核对原动作，等三个递增的地图时戳，再用新图重新计算 | 首段被取消，恢复后实际改走 `(-0.55,-0.05)` m。可以在播放器展开每次决策的观测来源 |
| 后续复查地点 | 读取刚保存的初图，从有成功停车回执的位置中选择与家、当前车位均有距离且可达、净空足够的候选；途中继续使用最新地图 | 选中第二段实际停下的 `(-0.496,-0.053)` m。抵达后等更新的地图，用一米半径重新统计，并核实车速 |
| 返航点 | 使用首次观测的家位置；用最新地图规划安全短段，每段核验执行回执 | 末端既有车载定位，也有独立仿真位姿，可比较两者 |

坐标单位为米，属于本次启动的局部里程计坐标系。前沿是“向这里靠近，有望看到更多未知栅格”；短目标是底盘这次可以执行的动作。返回 `SUCCEEDED` 还需要到点回执、位置证据和任务验收。[前沿选择](../../exploration/frontier.py) · [选复查点](../../tests/system/campus_revisit.py) · [分段执行与恢复](../../tests/system/campus_survey_worker.py)

## 二、跟着录像核对实验

| 视频时间（仿真原速） | 当时发生了什么 | 怎么判断 |
|---|---|---|
| 约 0.5 秒 | 提交中文任务，等待车载感知。测试程序延迟启用感知 | 归档中尚无地图；执行器只报告等待 |
| 约 8.5–12.2 秒 | 首段起步转向时暂停融合感知。车身转了约 68°；执行器发现消息过期，按原动作 ID 请求取消并等待停车回执 | 从确认停车到观测恢复共 3.286 个仿真秒，24 个世界位姿样本的漂移为 0，17 条速度指令均为 0，期间没有新目标。这次未测量高速平移时的制动距离 |
| 约 12.2–22.3 秒 | 测试程序恢复感知发布。车自己等足三幅新图、重选路径、到点并保存初图 | 局部范围内，初始 1,419 个已知格，存图时 1,903 个，增加 484 格，即 4.84 m² 的新增已观测面积 |
| 约 22.3–29.7 秒 | 从初图和到点记录选复查站，沿已知自由空间返回该站，停稳后重新观测 | 独立位姿距所选目标约 5.82 cm。车速与角速度都为零，周边一米内 315 格均为自由；独立录下的同帧地图复算一致 |
| 约 33.9 秒 | 回到出发位置并停稳 | 车载估计距家 5.08 cm；Gazebo 独立位姿距起点 4.47 cm，整段实际行驶约 1.98 m |

全程一次 Agent 提交、一个工具操作、五段底盘动作，其中一段取消、四段成功。五次派点都有原始栅格与独立地图订阅逐格匹配。故障的引入与解除由测试程序负责；停车、等待、重新选点、复查和返航由任务执行器负责。另一次无发布者的隔离 ROS 测试中，等待预算耗尽后任务以 `BLOCKED` 退出，零动作。它展示的是持续无感知时的处理边界。[实验总回执](../../artifacts/verification/unknown-campus/mission-02/acceptance.json) · [世界位姿和栅格审计](../../artifacts/verification/unknown-campus/mission-02/campus-audit.json) · [传感器持续缺失负例](../../artifacts/verification/unknown-campus-negative/no-stream.json)

## 三、这次结果能支持哪些工程判断

使用已有大型校园世界，保留 566 个碰撞元素。为能从俯视相机看见车，观察相机隐藏教学楼上层可视模型。车在教学楼入口附近首次启动；将平面扫描量程设为 2.1 m，让在线地图能随行驶增长。任务限定约 6×6 m，底层使用平面激光、里程计和 IMU 的本地融合，工厂标定来自有机号的仿真工装。可以验证首次选路、局部地图交接、失流停车与复用地图完成下一项工作。整个校园的全局 SLAM、跨楼层定位、语义识别、真机传感器装配外参和小时级运行仍需各自实验。复查站位于空旷区域，本次复查只证实占据状态。[世界来源和配置差异](../../artifacts/verification/unknown-campus/mission-02/campus-world.json)

第一次试跑 `mission-01` 已保存初图并返航。验收脚本当时错误地读取不存在的时间字段，原始总回执记为失败。审计修复后用同一份观测复算通过，并从空状态重新跑了本页包含停车复查的 `mission-02`。本页数值均来自第二次任务。

## 四、复现和扩展

先准备本仓库仿真镜像及校园资源。命令采用新的输出目录，实验使用独立 Compose 项目、任务存储、ROS 域和 Gazebo 分区。默认在本机已有的校园卷或资源上建立仿真副本。[校园资源准备](../../scene/campus_large/README.md)

```sh
python tests/system/record_unknown_campus.py --image edge-agent-ros:v0.1 --out artifacts/verification/unknown-campus/my-run
```

没有 Gazebo 也能复核本次结果。在仓库根目录运行以下命令，将原件解压到新目录后，审计程序会重算各段地图净空、故障停车、复查与返航。压缩包内含 268 个文件，包括逐帧相机、各源时间线、原始决策栅格、初图及复查回执。

```sh
python -m zipfile -e artifacts/verification/unknown-campus/mission-02/recording-export.zip artifacts/verification/replay-campus-02
python tests/system/unknown_campus_world.py artifacts/verification/replay-campus-02 --audit-recording campus-e7962f38e9
```

下一台车可以直接使用通用录制插件；本次受控探索工具仍限定在独立 Gazebo 环境。接入真实运动前，应重新验证外参、时间同步、真实制动距离与定位丢失后的停机策略。[按任务启停录制](../../task_recorder/README.md) · [实验验收契约](../specs/SDD-043-unknown-campus.md)
