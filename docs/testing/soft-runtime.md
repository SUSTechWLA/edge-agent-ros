# P1 的复测入口与试点范围

本轮把一个已批准的纯软件包从发布、注册、自然语言规划一直追到原绑定和卸载。固定 P0 基线为 `f0f7dbf`。在独立 Compose 项目打开 soft 工作流，机器人上的已有启动配置继续解释既有任务和 v1 绑定。

| 必测边界 | 观测者与通过条件 |
|---|---|
| Context / Fiber | 插件登记工具、服务与监听。记录实际调用顺序，逆序异步清理完成一次。apply 半途失败、并发卸载、依赖消失、清理失败都要有独立断言。 |
| 发布与权限 | 并发竞争同一修订只允许一个成功；内容与受信制品、schema 或部署权限不匹配时拒绝。容器级探针确认 soft 无设备与执行器路由。 |
| 冻结与恢复 | 用相同任务 ID 重放，保存原计划和操作号。排空时已预约的旧步骤可以完成，新的计划停止准入。重启、回执丢失和验收器不可用均需保留原绑定。 |
| 三个真实消费者 | 同时观察 Evidence HTTP、Session 请求前后绑定、Derived 数列的独立计算结果。旧里程计读取、inspect/status 与现场策略沿仓库原入口回归。 |
| 清理 | 以真实调用者和冻结数据判断一条旧路径是否还能删除。审查 Python 导入、CLI、镜像入口、Compose、受管目录和已持久化的步骤；能被旧调用者触达的一条路径须保留并测试。删除后从干净目录重新运行 golden、单元、容器和整套系统回归。 |

原始失败轮次独立留存。测试结果按运行标识、提交、命令、观察值和证据位置登记。尚未执行的工位试验不能由软件回归代替。

## 本地实测

候选 Docker 项目 edge-test-soft-03257daaab7d 执行 6 个任务，结果为 5 个成功、撤回能力后 1 个预期阻止。派发期间暂停 Evidence，排空记录保留 1 个原操作；恢复后由原绑定完成。两次装载共产生 10 条生命周期迁移。Linux Agent 容器、PID 和进程启动时刻均保持一致。3 个 soft 容器逐一检查设备、有效网络和控制请求拒绝。原始报告位于 .ci-results/sdd-045/p1/container-candidate-03/report.json；candidate-01 保留 Session 旧协议摘要格式失败，candidate-02 保留测试规划器未隔离引起的时限失败。

在 0aab629 对应的实现中，17 个 Fiber、11 个宿主、9 个描述符、9 个注册表单测覆盖首次探测、失联、热更新、撤销、改配置后重启、65 个结算失败项的公平调度等边界。结算调度另有单独的 ROS 镜像内任务账本测试。18 个字节级 v1 对照结果来自 8520e43。只删除已替代或无调用的分支与管理指令；经核查，legacy Derived 里程计读取、普通 HTTP 调用和旧清单解析仍服务原任务。
