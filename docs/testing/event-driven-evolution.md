# 从一次能力缺口到可热装工具的系统验收

本轮在 Windows 工作站的隔离 Linux Docker 工程内验证 Edge Agent ROS。用户任务、作者决定、私有设计、代码候选、独立验收、正式注册以及工具执行分别取证。测试代码和镜像的基点为 `9c75bbe`。下表区分协议是否走通、模型能否生成合适实现、真实任务是否执行成功。

## 两个容易混淆的“成功”

| 实验 | 起点、观察者与成功条件 |
|---|---|
| 原任务自动获得一份设计 | 一次“读取 PNG 宽高”的自然语言提交触发 Agent 原生规划受阻，已有作者给出可核查的拒绝，设计订阅者查收事件及私有收据。实际 Agent、Console 和持久卷参加。独立探针统计模型、设备调用，黑盒重建 Console 归档并重启订阅者。查到同一个源事件、原设计和终态才算交付成功；读取图片宽高仍需新的开发与任务验收。[黑盒](../../tests/system/plugin_design_acceptance.py) |
| 已安装的工具完成新任务 | 能力缺口 `word-gap` 仅描述需要的新运算。自动设计和编码插件生成独立候选。验收方另持样本并显式批准，随后用新的 `word-active` 任务提交实际正文。检查工具绑定版本、原文摘要、独立期望、重复提交和卸载后历史。前置作者的拒绝用固定夹具给出，以便直接比较后面的模型设计和编码。实际注册、HTTP 提供者和 Agent 均参与。[黑盒](../../tests/system/software_provider_acceptance.py) |
| 验证模型能力边界 | 固定协议回复验证完整词频调用能获得 2，空串获得 0。真实 Qwen 的大写转换要通过含空串、Unicode、制表符和末尾空格的独立样本。真实词频另作质量探针，逐次记录所选接口、模型终止与代码验收结果。固定回复的通过数与真实模型的完成数分别统计。[各次正反样本](../evidence/software-author-acceptance.json) |

## 故障和对照

**总线积压的实测分母。** 外部探针生成 64 条预热事实，实际停掉 Console，再让生产者提交 1,024 条事实。从启动 Console 到对外能查齐 1,088 条共用时 19.891 秒。材料可见后，两个消费者分别用 0.381 秒、0.328 秒追平，各收到 1,088/1,088 条，身份、顺序、载荷与外部见证一致，重复为 0。重新用空游标读取的结果仍一致。暂停期间一个消费者实际探测了故障，两个进程的重复读取只产生一条阻塞记录；另一消费者全程离线。此工况主要等待归档导入。计时包含启动，单次 amd64 合成负载不能估算板端持续吞吐。[独立验收程序](../../tests/system/event_backlog_probe.py)

- **错误归档与慢响应。** 注入序号乱序、同一位置内容冲突、错误来源、虚构父位置、页截断、DNS 等待或持续滴流。检查整页回滚、最后的有效游标、跨重启只有一次阻塞与一次有因果关系的恢复。独立超时包含连接和读取全过程。[归档用例](../../console/server/test_event_sink.py) · [订阅与网络实验](../../tests/test_plugin_design_watch.py)
- **进程死在写盘与确认之间。** 正常重启应认回原私有草案；若该文件被恢复为不同目标，即使 JSON 合法，也必须得到 `draft_conflict`。提交前的摘要、归档的确认以及最终文件三者可分别取证。编码阶段同样检查丢确认和预算用尽。[设计恢复](../../tests/test_plugin_design_watch.py) · [候选恢复](../../tests/test_software_author_watch.py)
- **越权与错误成功。** 变更独立样本会使原批准摘要失效；卸载旧版不得覆盖新版本。将模型输出截断、伪造来源或替换接口，只能进入重试、跳过或人工复核。用两份实际 Compose 冷启动及独立读写探针核查，设备、Docker 套接字和工具注册卷均未挂给设计与编码进程。[部署实验](../../tests/system/evolution_mounts.py)
- **真机与长稳。** 本轮板端 Compose 在桌面 Docker 测试。实际 RK3588 / Jetson 上的温升、设备失联后的控制权移交、断电后源卷损坏、24 小时 Docker 与 72 小时板卡持续运行另列阶段门槛。[迭代路线及指标](../architecture/plugin-evolution.md)

## 复跑

在仓库根目录执行。需要本机 Docker、ROS/Gazebo 的项目构建环境及已缓存模型的 Ollama 卷。系统套件为每轮创建临时工程和独立日志目录。

```powershell
python tests/system_suite.py --ollama-cache-volume edge-agent-ros_models
```

系统套件的原始阶段日志和数值位于 `.ci-results/system/runs/<运行号>/`。词频模型的独立探针使用验收程序的 `--automatic --scenario word-count --model-cache edge-agent-ros_models`。若目标未实现，探针返回失败并留下实际终止原因。[安装、查询与撤回](../plugin-evolution-operations.md)
